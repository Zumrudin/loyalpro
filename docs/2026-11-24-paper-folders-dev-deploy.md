## Исправление списка и первичности, 24.11.2026

После пользовательской проверки на 26.11.2026 обнаружены две причины:

1. Запись могла иметь `client_id=NULL`, хотя карточка уже присутствовала по `yclients_client_id` того же салона. INNER JOIN скрывал такую запись из списка; сверщик также её не учитывал.
2. `visits_count` из YClients мог включать будущую первую запись. Значение1 ошибочно трактовалось как доказательство состоявшегося посещения.

В `services/paper-folders.js` добавлено сопоставление по YClients ID только при пустом локальном client_id и строго внутри салона, во всех путях чтения/сверки. Неизвестные карточки не скрываются. Первичность использует явный `client.is_new` из актуального снимка записи, при этом факт состоявшегося визита/last_visit_at имеет приоритет. Общий счётчик используется только при отсутствии явного признака.

Проверка чтением dev-данных до установки: список исправленной версии содержит две записи; изменения записей/карточек для исправления связи не требуются. Обновляется только файл сервиса; схема, frontend и сторонние интеграции не меняются. Backup и журнал установки: `/srv/loyalpro-dev/updates/paper-folders-fix-20261124/`.

Исправление установлено заменой одного сервиса с сохранением предыдущей версии и перезапуском dev `loyalpro`. На старом коде три регрессионных сценария воспроизводят дефект; на исправленном — 30/30 PostgreSQL-проверок, 128 Jest-тестов и 5 node:test PASS. Проверка версии сервиса, старта с БД и закрытого API PASS. Физические записи клиентов и их связь не переписывались; номера выдаются штатным фоновым сверщиком.
