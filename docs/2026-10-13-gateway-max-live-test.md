## Что проверяет ТОЛЬКО владелец (нужен телефон с тестовым номером +79200255591)

1. Дев-админка → Настройки → Мессенджеры → «Подключить MAX напрямую» (или «Запустить заново» у строки MAX) → на телефоне MAX → Профиль → Устройства → Подключить устройство → сканировать QR. Ожидание: строка `ready` с номером и именем, лог шлюза `готов: 79200255591 (…, id N)`, канал `max` салона переключился на шлюз (`messenger_accounts` #10 `active`, Chatpush `max` #3 `disabled`). **N обязан быть 62232990** — это id того же номера в данных Chatpush (`chatpush_events`, группа администраторов, `sender_id`). Совпадение доказывает общее пространство id: отправка по `max_user_id` старых диалогов уйдёт тому же человеку. Не совпало — прод не выкатывать.
2. С номера клиники 79250177778 написать текст в MAX → в «Чате» входящее; лог шлюза: строка «диалог …: участник …, XOR даёт … — совпадает/НЕ совпадает» (проверка формулы id диалога) и есть ли номер собеседника (`sender_phone_number`).
3. Прислать фото и файл → `file_data` в вебхуке, файлы в `frontend/uploads/gateway/10/`.
4. Ответить из «Чата» текстом и файлом на 79250177778 → доставка `g<n>` «Отправлено», эхо с `delivery_id` в «Чате», на телефоне 79250177778 сообщение пришло.
5. Набрать ответ руками на телефоне +79200255591 → в `chatpush_messages` `authored_by='operator'`, диалог на паузе («ответил оператор»).
6. `pm2 restart loyalpro-gateway` → аккаунт снова `ready` без QR.
7. Догон пропущенного (правка 14.10.2026, ответ `CHAT_HISTORY` живьём не проверен): `pm2 stop loyalpro-gateway` → с 79250177778 написать 2 сообщения в MAX → `pm2 start loyalpro-gateway`. Ожидание: аккаунт `ready` без QR, в логе шлюза `догон после обрыва: чатов с движением N, запрошено M, сообщений новее границы K, переслано 2`, оба сообщения в «Чате» по порядку и ровно по одному разу (а не дважды — если сервер сам дошлёт их push'ем, второе пересылание отсечёт `recentIds`/UNIQUE в бэкенде). Если в логе `переслано 0` при сообщениях в «Чате» — их дослал push (тоже годится, записать); если сообщений в «Чате» нет — догон не сработал, прод не выкатывать.
8. Альтернативно/дополнительно — `cd gateway && node scripts/max-spike.js --to 79250177778 --file /tmp/a.jpg` (сырые push-кадры в лог; сессия `data/spike-max`, удалить после).

Записать сюда дословные строки лога по каждому пункту; при расхождениях — см. план, Task 11 Step 3 (что менять при «XOR НЕ совпадает», скрытых номерах, отсутствии push на свои сообщения, отсутствии `NOTIF_ATTACH`).
