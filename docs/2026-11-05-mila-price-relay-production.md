## Причина перевода на администратора

Запрос прайса не доходил до отправки картинок: Polza отклоняла генерацию с HTTP 402 из-за недостаточного баланса. При ручном выборе Astra первый запрос переключал провайдера обратно на Polza.

В конфигурации текущего прод-релиза отсутствовали `MILA_CODEX_RELAY_URL` и `MILA_CODEX_RELAY_SECRET`. Изолированный вызов адаптера воспроизвёл `RELAY_CONFIG`; запись маршрутизации зафиксировала переход `gpt → polza` с причиной `bridge_unavailable` в 17:37:36 МСК. Мост на dev при этом был запущен. Момент и причина утраты параметров не установлены.

С разрешения владельца восстановлены адрес HTTPS-моста и общий ключ в `/srv/loyalpro/current/backend/.env`. Ключ взят из защищённой конфигурации работающего dev-моста и не включён в репозиторий. Сохранена копия `.env.before-relay-20261105`, права файла конфигурации — 0600. Перезапущен только процесс `loyalpro` под пользователем `loyalpro` с `PM2_HOME=/srv/loyalpro/.pm2`. Через штатный сервис маршрутизации выбран `gpt`; итоговая модель — `gpt-6-astra`, состояние — `ok`.

При следующих релизах необходимо сохранять оба параметра моста в конфигурации нового релиза. Наличие параметров не доказывает работоспособность: после изменения выполнять синтетический smoke-тест из backend (`node -r dotenv/config scripts/mila-codex-relay-smoke.js`). Ключи и содержимое `.env` не выводить в отчёты или логи.
