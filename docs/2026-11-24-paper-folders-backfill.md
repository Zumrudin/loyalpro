# Первичная алфавитная нумерация папок — 24.11.2026

По прямому запросу владельца присвоены номера существующим пациентам; уточнение: только состоявшиеся записи, перенумеровать всех. Выполнено на production `loyalpro`, salon_id=1. Dev первоначально не менялся; позднее применено по отдельному запросу, см. ниже.

## Правила и результат

- Отбор по существующей локальной истории: хотя бы одна запись `arrived/completed`, время не в будущем, без признака удаления. Связь по client_id или, если его нет, по yclients_client_id внутри того же салона. Оплата не обязательна. Отмены/неявки не учитываются. Отсутствующая в локальном зеркале история извне не загружалась.
- 1672 пациента получили номера 1–1672 по сохранённому ФИО, `Intl.Collator('ru', sensitivity=base)`, при равенстве — id. Пустое имя, наличие архивных папок или превышение вместимости останавливают операцию.
- Шесть предварительных резервов пациентов без состоявшихся визитов перенесены на 1673–1678 с сохранением их состояния. Свободно 322 места.
- Исторические номера закреплены (`committed=true`), физическая отметка `prepared` сохранена, новым строкам не выставлялась. Договоры и записи не изменялись.
- Одна транзакция под тем же advisory lock, что штатный allocator; timeout ожидания блокировки 5 секунд, каждого запроса 30 секунд. Перед перестановкой номера освобождены внутри транзакции для соблюдения UNIQUE; события released/registered/reserved сохраняют аудит. Максимум 2000 папок, чтение только указанного салона. API и схема не менялись; deploy/restart не требовались.

## Инструмент и проверки

`backend/scripts/paper-folders-backfill.js --salon=1 --database=loyalpro`: по умолчанию READ ONLY. Запись требует `--write --backup=/private/new-file.json`; snapshot создаётся эксклюзивно с правами0600 и fsync до изменений. `--backend` задаёт каталог существующего backend с конфигурацией и зависимостями. Не запускать автоматически/по расписанию: новые пациенты могут изменить алфавитную последовательность при следующем намеренном полном запуске.

- `node backend/scripts/paper-folders-db-test.js --filter=backfill`: PASS (DDL дважды + интеграционный сценарий). Реальная изолированная PostgreSQL15, синтетические данные: алфавит, состоявшийся неоплаченный визит, отсутствующий local client_id, отмена, будущая запись, конфликт резерва, другой салон, dry-run, повтор без новых событий, права backup, лимит2000, отказ при архиве.
- Production dry-run: eligible1672, occupied6→1678, changed1678, moved6.
- Production запись: те же счётчики, соответствие всех назначений проверено до commit.
- Повторный production dry-run: changed0, moved0.
- UI/browser, полный Jest и мобильный lint не запускались: интерфейс и API не менялись.

## Восстановление

Приватный snapshot прежних строк и плана: `/srv/loyalpro-backups/paper-folders-alphabet-20261124/before.json` на production. Имена и контакты в snapshot не копировались. Одноразовый исполняемый файл: `/tmp/paper-folders-backfill-20261124.cjs`.

До commit любая ошибка откатывает транзакцию. После commit восстановление выполнять только отдельной согласованной операцией под tenant advisory lock, сравнив текущие строки и события с моментом перенумерации. Не перезаписывать последующие ручные/автоматические изменения. Вернуть прежние номера/флаги существующих строк, для новых строк снять назначение только после проверки последующих событий; аудит сохранить и зафиксировать обратные операции. Физические ярлыки папок сверить с восстановленными назначениями. Прямое восстановление всей БД не требуется.
