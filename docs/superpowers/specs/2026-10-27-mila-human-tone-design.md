# Мила «как живой человек»: стилевой слой в коде и модель GPT-6 Astra на мосту

Дата: 2026-10-27. Статус: дизайн утверждён владельцем 27.10.2026 (вариант «А» из
обсуждения, ориентир стиля — живые администраторы PERI, обращение «Вы» с заглавной
сохраняется; модель моста — GPT-6 Astra как основная на деве и проде).

## 1. Контекст и замер

Жалоба владельца: Мила на проде «общается как робот, длинные ответы, сложные
предложения». Замер по прод-БД за 14 дней до 27.10 (116 реплик Милы в 29 диалогах,
`chatpush_messages.authored_by='agent'`) против 1 671 реплики живых администраторов
за 30 дней (`authored_by='operator'`):

| Показатель | Мила | Администраторы |
|---|---|---|
| средняя длина | 144 зн. | 103 зн. |
| медиана длины | 140 зн. (2,4 предложения) | |
| реплик длиннее 250 зн. | 9 % | |
| markdown в тексте (`**15:30**`, `*   пункт`) | 28 % | 0 % |
| «Вы/Вас/Вам» с заглавной | 55 % | 10 % |
| «вы/вас/вам» со строчной | 13 % | |
| эмодзи | 23 % | 78 % (🤍 ✨ ☺️) |
| заканчивается вопросом | 43 % | |

Выводы замера:

1. Длина по цифрам не проблема. «Роботом» Милу делают пять конкретных вещей.
2. Markdown виден буквально: TDLib-шлюз отправляет `formattedText` с пустым
   `entities`, клиент MAX — простой текст. Промпт при этом сам велит «жирным
   выделяй только ключевое (например время)».
3. Обращение скачет внутри одного диалога: модель чаще пишет «Вы», а фразы кода
   («Передаю ваш диалог…», «Готово! Записала вас…») — «вы».
4. Представление «Здравствуйте, Полина! Я Мила, виртуальный администратор
   PERI CLINIC.» приклеено к ответу по делу в 22 случаях из 23, в том числе
   перед «Мне жаль, что прокол гноится».
5. Серии без ответа пациента: напоминание о себе через 15 минут и финал по
   умолчанию «Если появятся вопросы — напишите, будем рады помочь. Хорошего дня!»
   (`followup_final_text` у салона не задан). За 14 дней 7 серий из 3+ сообщений.
6. Канцелярит самой модели (прод — GPT-6 Sol через мост Codex): «не буду
   советовать продолжать обработку без оценки специалиста», «уточнили возможность
   осмотра».

Промпт уже содержит блок «ТОН ГОЛОСА» с теми же требованиями («как живой
администратор, а не бот», 1–3 предложения, без канцелярита, не каждое сообщение
вопросом); модель выполняет его частично. Поэтому новые правила в промпт не
добавляются (мораторий CLAUDE.md), пункты 2–5 закрываются кодом, пункт 6 —
сменой модели.

Скрипты замера этой сессии лежали в `/tmp` и воспроизводятся новым
`scripts/mila-style-metrics.js` (раздел 6).

## 2. Решения владельца

- Делать вариант «А»: стилевой слой в коде, без второго LLM-прохода.
- Ориентир стиля — реплики живых администраторов: коротко, 🤍/✨, «окошко»,
  «как Вам?».
- Обращение остаётся на «Вы» с заглавной буквы (владелец явно оставил).
- На мост подключить модель GPT-6 Astra и сделать её основной на деве и проде;
  тон дальше проверяется на ней.

## 3. Часть 1. Модель GPT-6 Astra на мосту

### 3.1. Как устроено сейчас

  шлёт подписанный запрос на `https://dev.zumrudin.ru/api/mila-codex/v1/message`.
  Мост — systemd-сервис `mila-codex-bridge` на деве, исходники в

- В каталоге Codex (`~/.codex/models_cache.json`, 27.10.2026) модель называется
  `gpt-6-astra`, display name «GPT-6-Astra», `default_reasoning_level: medium`.
  Живая проба через CLI: ответ за 7 с, `reasoning_output_tokens: 0` на коротком
  запросе. У `gpt-5.6-sol` в том же каталоге уровень low; прежний `gpt-6-sol` в

- Маршрутизация (`agent_model_routing`): активный движок `gpt`, при

### 3.2. Изменения

1. `codex.js`: `MODEL = 'gpt-6-astra'`.
2. `codex-relay-protocol.js`: `MODEL = 'gpt-6-astra'`; новый список
   `GPT_MODELS = ['gpt-6-astra', 'gpt-6-sol']` — модели, которые relay принимает
   в ответе моста для движка `gpt`. Для `claude` по-прежнему только
   `CLAUDE_MODEL`.
3. `codex-relay.js`: проверка ответа — `result.model` входит в допустимый список
   движка (а не равен одной константе); возвращаемый `model` — фактический из
   ответа моста, чтобы `agent_model_routing.model` показывал реальную модель.
   Любая другая модель в ответе по-прежнему `RELAY_RESPONSE`.
   ЗАЧЕМ список: мост и прод выкатываются не одновременно, и жёсткое равенство в
   окне между выкатами выбросило бы Милу на «Пользу» до ручного возврата.
4. `model-routing.js`: название и модель движка `gpt` берутся из констант
   протокола, подпись «GPT-6 Astra» (карта отображаемых имён
   `{ 'gpt-6-astra': 'GPT-6 Astra', 'gpt-6-sol': 'GPT-6 Sol' }`), то же для
   записи `codex`. `status()` и так предпочитает фактическую модель из строки.
5. Мост (`codex-bridge.js`, `mila-codex-bridge.js`) без правок: он берёт `MODEL`
   из протокола и из `codex.js`.
6. Модуль вердиктов (`services/dialog-verdicts/provider.js`) ходит через те же
   провайдеры и переключается вместе с ними; отдельных правок нет.
7. Уровень размышлений не задаём (остаётся default модели). Если реплей (3.4)
   покажет заметное замедление, отдельным решением добавляется
   `-c model_reasoning_effort="low"` в `codex.js`; заранее не делаем.

## 4. Часть 2. Стилевой слой

### 4.1. Модуль `services/agent/reply-style.js` (чистый, без БД/HTTP)

Экспорт: `stripMarkdown(text)`, `capitalizeAddress(text)`,
`applyReplyStyle(text)`, `isEnabled()`.

`stripMarkdown`:

- `**x**` и `__x__` → `x` (внутри одной строки или абзаца, нежадно);
- одиночные `*x*` и `_x_` → `x`, только когда маркеры вплотную прилегают к
  непробельным символам с обеих сторон и снаружи от маркера нет буквы, цифры или
  `_` (так «5*3» и подчёркивания в адресах не трогаются);
- обратные кавычки вокруг текста убираются;
- заголовки: ведущие `#…# ` в начале строки убираются;
- маркеры списков в начале строки (`* `, `- `, `+ `) → `• `; нумерованные
  списки и уже стоящий `• ` не трогаются;
- ссылка `[текст](url)` → `текст: url`;
- три и более переводов строки подряд → два; пробелы в конце строк убираются.

`capitalizeAddress`: формы вы, вас, вам, вами, ваш, ваша, ваше, ваши, вашу,
вашей, вашего, вашему, ваших, вашим, вашими, вашею как отдельные слова
(границы по `\p{L}`) → первая буква заглавная. Уже заглавные не трогаются.
Внутри слов («выбрать», «вашингтон» нет в русском адресате) не срабатывает.

`applyReplyStyle(text)` = `capitalizeAddress(stripMarkdown(text))`;
не-строка → `''`; идемпотентна (`f(f(x)) === f(x)`, закреплено тестом); эмодзи,
числа, времена, ссылки и переводы строк сохраняет.

`isEnabled()`: env `AGENT_REPLY_STYLE`; значение `'false'` выключает
преобразования (аварийный рычаг), по умолчанию включено. Рычаг гасит только
преобразования; переписанные фразы кода (4.3) от него не зависят.

### 4.2. Где применяется

1. `services/agent/dispatcher.js`, обёртка `send(meta, text)` — первой строкой
   `text = applyReplyStyle(text)`. Через неё идут все реплики Милы в диалоге:
   реплики модели, страховочные фразы (`handoverText`, `silentFallbackText`,
   `photoFailureText`), перевод при закрытии окна (`window-handover` зовёт тот же
   `send`), детерминированные подтверждения. Преобразование стоит ДО журнала
   авторства, `pendingReplies`, персиста в «Чат» и журнала доставок: эхо
   мессенджера приносит именно отправленный текст, и хэш авторства обязан
   считаться от него.
2. `deliverReplies`: список реплик преобразуется до цикла отправки, и в
   `additionalProposals.markSent` уходит уже преобразованный список (внутри
   `send` преобразование повторится — идемпотентно). `offered()` сверяет
   `deliveredText` с транскриптом, где лежит отправленный текст.
3. `services/agent/additional-proposals.js`, `prepare()`: текст предложения
   сохраняется как `applyReplyStyle(text)`. Модель копирует этот текст в реплику
   дословно, `markSent` проверяет `includes` — обе стороны обязаны быть в одной
   форме.
4. `services/agent/followup-worker.js`: `text = applyReplyStyle(text)` сразу
   после того, как текст напоминания стал окончательным (после бонусной строки),
   ДО захвата строки, который пишет `rendered_text` — в журнал ложится то, что
   ушло. Касается и напоминания stage 0, и финала.

Не применяется: тексты операторов, автоуведомления, касания «Заботы»,
напоминания о повторном визите (markdown у `system` за 30 дней — 0 из 1 541),
сообщения пациентов. Reply-guard и прочие проверки оркестратора работают ДО
слоя, на сыром тексте модели: времена и факты слой не меняет.

### 4.3. Приветствие и представление (`services/agent/greeting.js`, промпт)

Новая форма первого сообщения:

```
Здравствуйте, Полина!🤍
Это Мила, виртуальный администратор PERI CLINIC.

<ответ по делу>
```

- `buildGreeting({ givenName, salonName, empathetic })` →
  `Здравствуйте${имя ? ', ' + имя : ''}!${empathetic ? '' : '🤍'}\nЭто Мила,
  виртуальный администратор ${салон}.`; имя через `sanitizeName`, название
  салона через `resolveSalonName`, как сейчас.
- `ensureGreeting` склеивает `${greeting}\n\n${реплика}` (как сейчас);
  `empathetic` считает сам модуль по всей серии реплик:
  `EMPATHY_RE = /(жаль|сочувств|извин|простите|прошу прощения|передаю)/i`.
  Так 🤍 не попадает перед сочувствием, извинением и переводом на администратора.
- `buildIntroduction` → `Это Мила, виртуальный администратор ${салон}.`
- `ensureIntroduction`: если первая реплика начинается с приветственного
  предложения (`LEADING_GREETING_RE`) — представление встаёт отдельной строкой
  сразу после него, затем пустая строка и остальной текст без ведущих пробелов;
  иначе `${представление}\n\n${реплика}` (как сейчас).
- `INTRO_RE` дополняется формами `это\s+Мила` и `на\s+связи\s+Мила` — узнавать
  надо и старую, и новую форму, иначе представление задвоится.
- Образцы «ПЕРВОГО сообщения» в промпте (три ветки блока ИДЕНТИФИКАЦИЯ ПАЦИЕНТА)
  переводятся на ту же форму: известный пациент —
  «Здравствуйте, ${имя}!🤍 / Это Мила, виртуальный администратор ${салон}. /
  (пустая строка) / Чем могу помочь?»; незнакомый — «Здравствуйте!🤍 / Это Мила,
  виртуальный администратор ${салон}. / (пустая строка) / Подскажите, как могу к
  Вам обращаться и на какую процедуру хотели бы записаться?». Связь образца с
  `buildGreeting` закрепляется тестом (как сейчас для старой формулы).

## 8. Риски и допущения

- `capitalizeAddress` капитализирует любое «вы» как обращение к пациенту; в
  реплике Милы иного «вы» не бывает (цитат пациента она не пишет).
- Одиночные `*`/`_` в арифметике и адресах защищены условиями из 4.1; ложные
  срабатывания ограничиваются потерей символа форматирования, не смысла.
- Astra с `medium` reasoning может отвечать дольше Sol — порог и действие в 3.4.
- Образец промпта модель копирует не дословно (правило «образцы — ориентир»):
  форма первой строки может варьироваться, детерминированная дописка в коде
  срабатывает только при отсутствии приветствия/представления.
- `GPT_MODELS` содержит старый идентификатор ради окна выката; после выката на
  прод его можно убрать отдельным коммитом или оставить для отката.

## 9. Порядок работы

1. Модель: константы, relay, routing, тесты.
2. Стилевой слой: модуль, тесты, проводка в диспетчер, предложения, напоминания.
3. Приветствие и представление, образцы промпта, тесты.
4. Фразы кода и их тесты, placeholder на фронте.
5. Скрипт замера и его тест; снять замер «до» на проде.
6. Реплей Sol → Astra на деве (3.4), отчёт владельцу.
7. Слияние в `main`, мост, дев, прод (3.3), проверка на проде, замер «после»
   через неделю.
