# Чат v2 — двусторонняя переписка, группировка, SSE, файлы, эмодзи

Дата: 2026-07-27. Статус: одобрено пользователем.

## Проблема

Страница «Чат» (`frontend/js/pages/chat.js` + `routes/chat.js`) — read-only просмотр
переписок chatpush с 5-секундным полным переопросом. Жалобы:

1. Тормоза и задержки обновления, ошибки.
2. Сообщения не группируются в рамках одной переписки:
   - Telegram-групповой чат «разваливается» — сообщения участников с известным
     номером уходят в их личные диалоги (ключ `COALESCE(phone, chat_id)`);
   - половина диалогов называется «periclinic»: имя берётся из последнего
     сообщения, а оно исходящее (sender = аккаунт клиники).
3. Левая панель (300px, шрифты 11–13px) мелкая и нечитаемая.
4. Нет возможности отвечать из чата; нужен выбор мессенджера при ответе
   (дефолт — канал последнего входящего), вложения файлов, стандартные эмодзи.

## Решения (одобрены)

- Группировка: **клиент + группы отдельно** — личный диалог = номер телефона
  (все мессенджеры вместе), групповой чат = один диалог целиком по `chat_id`.
- Файлы: Chatpush умеет — `POST /api/v1/send_file` (multipart `file`, query
  `file_name`/`caption`/`type=image|document`/`dispatch_routing[]`, каналы
  whatsapp|tdlib|max, до 100 МБ, фото <10 МБ нативно). Найдено в dev-доках 27.07.
- Ручной ответ оператора → **авто-пауза бота** (upsert `agent_dialogs.status='escalated'`,
  reason `operator_reply`); возврат — существующей кнопкой «Вернуть боту».
- Обновления: **SSE-push** с сервера + инкрементальный поллинг раз в 30 сек
  как страховка.

## Архитектура

### Бэкенд

**Ключ диалога** (чистая функция в `services/chat.js`, юнит-тесты):
- `chat_id` начинается с `-` (группа TG/MAX) → ключ `g:<chat_id>`, phone игнорируется;
- иначе → `NULLIF(phone,'')`, fallback `chat_id`.
SQL в `routes/chat.js` использует то же выражение (CASE). Существующий индекс
`idx_chatpush_messages_dialogkey` дополняется индексом по новому выражению
(через `migrations.js`, `IF NOT EXISTS`).

**Имя диалога**: последнего **входящего** сообщения (`sender_name`), приоритет:
имя клиента из `clients` → sender_name входящего → номер. Для групп — имя группы,
в пузырях — имя автора сообщения.

**`services/chat-events.js`** — in-memory реестр SSE-подписчиков:
`subscribe(salonId, res)`, `emit(salonId, event)`, heartbeat 25 сек.
Вебхук после сохранения сообщения эмитит `{type:'message', dialogKey, message}`.

**Роуты (`routes/chat.js`)**:
- `GET /api/chat/stream?token=` — SSE (JWT через query, как для скачиваний).
- `GET /api/chat/dialogs` — как сейчас + `channels:[...]` (каналы, из которых клиент
  писал) и `defaultChannel` (канал последнего входящего).
- `GET /api/chat/dialogs/:key/messages?after=<ts>` — инкрементальная выборка.
- `POST /api/chat/dialogs/:key/send` — `{text, channel}`. Резолв идентификаторов
  получателя из истории (phone / tdlib_user_id / max_user_id) →
  `chatpush.sendMessage` c `dispatch_routing=[channel]` → upsert эскалации.
  Сообщение персистится **эхом** вебхука (как ответы Милы) — своих вставок в
  `chatpush_messages` нет (без дедупа).
- `POST /api/chat/dialogs/:key/send-file` — multer memoryStorage, лимит 25 МБ,
  image-or-document, прокси в `chatpush.sendFile` (новая функция в
  `services/chatpush.js`: axios + form-data multipart) + `caption` + эскалация.

### Фронтенд

- Сайдбар: 380px, шрифт имени 15px, превью 13px, аватар-инициал с цветом канала.
- Композер: авторастущий textarea (Enter — отправить, Shift+Enter — перенос),
  селектор канала (дефолт `defaultChannel`), скрепка (превью файла + подпись),
  палитра стандартных Unicode-эмодзи (вставка в позицию курсора), «Отправить».
  Вынесен в `frontend/js/pages/chat-composer.js`.
- Оптимистичный пузырь ⏳ → замена эхом из SSE; ошибка — пометка + «повторить».
- SSE-приход: **append** нового сообщения в DOM (не перерисовка всей истории),
  подъём диалога в списке. Поллинг-страховка 30 сек, инкрементальный.
- Группы: имя автора над пузырём.

## Ошибки

- Отправка упала (Chatpush 4xx/5xx) → 502 с текстом, фронт помечает пузырь ошибкой.
- SSE-соединение умерло → EventSource авто-reconnect; страховочный поллинг
  не даёт потерять сообщения.
- Файл: неподдерживаемый mime/размер режется на фронте и в multer-фильтре.

## Не делаем (YAGNI)

Статусы прочитанности, поиск по тексту сообщений, цитирование (reply),
голосовые, счётчик непрочитанных.
