# Дизайн: де-эскалация агента Мила (спасти диалог перед переводом)

Дата: 2026-07-19
Статус: согласован, готов к плану

## Проблема

Клиент написал агенту Мила негативное сообщение («ты глупая ии и ничего не
понимаешь»). Модель сразу вызвала `escalate_to_operator`, диалог перешёл в
статус `escalated`, и Мила **молча** перестала отвечать. Клиент этого не понял и
писал дальше без ответа.

Две первопричины:

1. **Поведение.** `system-prompt.js`, Сценарий 3 предписывает при любом конфликте
   сразу эскалировать. Нет попытки извиниться, уточнить причину и спасти диалог.
2. **Молчаливость (баг доставки).** `system-prompt.js:62-63` велит модели вместе с
   вызовом `escalate_to_operator` отправить прощальный текст. Но
   `dispatcher.js:49-55` при `res.escalated === true` **выбрасывает все реплики
   этого хода**, включая объявление о переводе. Клиент не получает ничего.

## Требования (со слов пользователя)

- При негативе Мила должна **сначала попытаться спасти диалог**: извиниться,
  деликатно уточнить, что именно не понравилось, попробовать помочь сама.
- Переводить на администратора — только если спасти не удалось / клиент прямо
  просит человека / вопрос вне её компетенции.
- Перевод должен быть **явным** (клиент видит сообщение о переводе), а не молчаливым.
- Финальную фразу перевода модель формулирует **живо** (варьирует по контексту), а
  не строго фиксированный текст.
- Механику «после эскалации бот молчит навсегда, пока статус не сбросят вручную»
  **оставляем как есть** (`orchestrator.js:32` не трогаем).

## Границы (out of scope)

- Не добавляем счётчик негативных ходов / авто-эскалацию по лимиту в БД (решение
  «пора переводить» остаётся на суждении модели).
- Не меняем гейт допуска, вебхук, дебаунс, историю.
- Не меняем поведение «молчания после escalated».
- Не добавляем авто-разэскалацию (возврат в `bot` — только вручную/из админки).

## Решение

Подход: **промпт + точечный фикс dispatcher**. Минимум кода, закрывает обе
первопричины.

### 1. system-prompt.js — переписать Сценарий 3

Двухшаговый флоу с явным запретом уходить в тишину:

```
СЦЕНАРИЙ 3 — Недовольство, конфликт или перевод на человека:
Действуй в два шага и НИКОГДА не замолкай.

ШАГ А — Сначала попробуй спасти диалог (по умолчанию при негативе):
Если пациент недоволен, раздражён, критикует тебя или легко жалуется — искренне
извинись, спокойно и доброжелательно уточни, что именно пошло не так / не понравилось,
и предложи помочь ещё раз. Не спорь и не оправдывайся. Одно уточнение за сообщение.

ШАГ Б — Явный перевод на администратора:
Переходи к переводу, только если: (1) пациент прямо просит человека; ИЛИ (2) после твоей
попытки недовольство сохраняется; ИЛИ (3) серьёзная жалоба/конфликт/нестандартная ситуация,
которую ты не решаешь сама; ИЛИ (4) сложный вопрос / база знаний не дала ответа.
Тогда вызови escalate_to_operator и в ЭТОМ ЖЕ сообщении явно объяви о переводе, например:
«Мне жаль, что так вышло. Передаю ваш диалог администратору клиники — он подключится
с минуты на минуту и поможет лично 🤍». Больше ничего не пиши.
```

Замечания:
- Чистый негатив → сначала ШАГ А; прямая просьба человека / пустая база → сразу ШАГ Б.
- Фраза перевода — пример, модель варьирует (живой текст).
- Ссылки из Сценария 1 и базовых правил на «Сценарий 3» остаются валидными.

### 2. dispatcher.js — доставлять сообщение хода эскалации

Заменить блок `if (!res.escalated) { … }` (строки 49–55) на логику, которая
доставляет текст и на ходе эскалации, со страховкой от пустого текста:

```js
const DEFAULT_HANDOVER_TEXT =
  'Передаю ваш диалог администратору клиники — он подключится с минуты на минуту 🤍';

const replies = (res.replies || []).filter(t => t && t.trim());
if (res.escalated && replies.length === 0) {
  await send(meta, DEFAULT_HANDOVER_TEXT);   // страховка: никогда не молчим при эскалации
} else {
  for (const text of replies) await send(meta, text);
}
```

Инвариант: **при эскалации клиент всегда получает сообщение** — либо живую фразу
модели, либо дефолтную страховку.

Что НЕ меняется: `orchestrator.js:32` (пустой ответ на уже-`escalated` диалог) —
молчание после перевода сохраняется.

### 3. Операционно — оживить застрявший диалог #37

Диалог пользователя (`dialog_key = 79200255591`, id 37, salon_id 1) сейчас
`escalated`. Разово вернуть в `bot`, чтобы Мила отвечала и можно было
перетестировать:

```sql
UPDATE agent_dialogs SET status='bot', escalated_reason=NULL, updated_at=now()
WHERE id=37;
```

## Тестирование

Юнит-тесты (в духе существующих `*.test.js` в `services/agent/`):

- **dispatcher**: `res={escalated:true, replies:['текст перевода']}` → `send`
  вызван с этим текстом (сейчас бы не вызвался — регресс-защита от молчания).
- **dispatcher**: `res={escalated:true, replies:[]}` → `send` вызван с
  `DEFAULT_HANDOVER_TEXT`.
- **dispatcher**: `res={escalated:false, replies:['a','b']}` → оба доставлены
  (существующее поведение не сломано).
- **system-prompt**: сгенерированный промпт содержит маркеры «ШАГ А» и «ШАГ Б» и
  инструкцию не замолкать.

Ручная проверка на dev: написать боту негатив → ожидать извинение+уточнение (не
тишину); затем прямо попросить человека → ожидать явную фразу перевода и переход в
`escalated`.
