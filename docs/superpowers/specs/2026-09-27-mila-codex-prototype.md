# Мила: dev-прототип Codex по подписке

## Область

Запрос: проверить замену LLM-посредника на Codex с входом через ChatGPT, без
OpenAI API-ключа. Первая версия запускается отдельной командой на dev, использует
вымышленные диалоги и результаты инструментов. Рабочая Мила не переключена.
БД, CRM, отправка сообщений, схемы данных и настройки продакшена не меняются.

## Реализация

`backend/services/agent/providers/codex.js` реализует существующий контракт
`createMessage` / `toolResultMessages`. `getProvider('codex')` выбирает адаптер;
каждое обращение требует `MILA_CODEX_PROTOTYPE=true` и dev-контекст, иначе
завершается до запуска процесса. Dev-контекст — `NODE_ENV=development` для
отдельных прогонов либо `MILA_CODEX_DEV_STAND=true` вместе с БД
`loyalpro_test` для сервера стенда. Сервер сохраняет `NODE_ENV=production`,
чтобы не включать отладочные ошибки Express.

Используется установленный Codex CLI (проверено на 0.154.0), `codex exec --json`
с JSON Schema результата. Это адаптация через структурированный ответ, НЕ
нативные function calls App Server. Модель возвращает текст или список запросов
инструментов; их исполняет вызывающий код. В smoke это исключительно локальная
заглушка. При дальнейшей интеграции исполнение должно остаться в оркестраторе
Милы со всеми проверками салона, записи и повторных действий.

На каждый запрос создаётся отдельная ephemeral-сессия, история передаётся явно.
Общих session/thread ID между клиентами нет. Инструмент не может добавить
необъявленный параметр, включая `salon_id`; серверный контекст салона по-прежнему
обязан задавать оркестратор. Проверяются имена, JSON-объект аргументов, обязательные
и неизвестные поля. Полная проверка типов/доменов аргументов остаётся задачей
существующих обработчиков; это не новый универсальный JSON Schema validator.

## Запуск на dev

Из корня репозитория:

```bash
codex login status
NODE_ENV=development MILA_CODEX_PROTOTYPE=true node backend/scripts/mila-codex-prototype.js
```

Если вход отсутствует, владелец подписки выполняет `codex login --device-auth`
и завершает вход в браузере. Копировать ключи или токены в репозиторий не нужно.
Прототип принимает только вход через ChatGPT; вход с API-ключом отклоняется.
Скрипт не читает `.env`, не импортирует БД, диспетчер или реальные инструменты.
Выводит только статусы, длительности и размер ответа, без текста диалога.

Дополнительные переменные (задаются оператором, не клиентским запросом):

- Модель закреплена в адаптере: `--model gpt-6-sol` в каждом вызове. Старый
  `MILA_CODEX_MODEL` больше не используется; автоматического выбора другой модели нет.
  Новые отчёты сохраняют запрошенную модель. Ранее полученные ответы не переименовываются.
  Для дев-стенда проверен CLI **0.157.1**. Старая версия 0.154.0 получала
  отказ `not supported when using Codex with a ChatGPT account` и каталог без
  GPT-6 Sol. После обновления, с тем же аккаунтом и аргументами, модель доступна:
  живой smoke прошёл вызов инструмента и финальный ответ. Это была проблема
  версии CLI в данном окружении, а не доказательство отсутствия модели в подписке.
  Установленный CLI обновлён командой `npm install -g @openai/codex@0.157.1`.
  Дополнительно прошёл живой кейс `price` через полный промпт v1 (95 954 символа)
  и штатный оркестратор: 7,023 с, один вызов модели, без отправок и изменений CRM.
  Отчёт: `/tmp/mila-codex-sol-verified.json`. Полный дневной набор заново не прогонялся.
- `MILA_CODEX_BIN`: путь до CLI, по умолчанию `codex`.
- `MILA_CODEX_TIMEOUT_MS`: 1000–180000, по умолчанию 90000; проверка входа имеет
  отдельный таймаут 10000 мс.

`AGENT_PROVIDER` и `.env` для отдельного smoke менять не требуется. На этапе
первоначального прогона dev-диспетчер не переключался. Подключение чата стенда
описано ниже. Серверный режим с боевой БД заблокирован адаптером.

## Изоляция и отказы

- stdin передаёт промпт, история не попадает в аргументы процесса.
- Дочерний процесс получает ограниченный набор переменных окружения, без
  API-ключей, DB/CRM/Chatpush-секретов и `NODE_OPTIONS`.
- CLI игнорирует пользовательский config/rules; рабочий каталог — отдельный
  пустой `/tmp/mila-codex-*`, проектные инструкции отключены. Используется
  существующее местоположение авторизации Codex, без копирования токенов.
- Отключены shell, Code Mode, приложения, плагины, браузер, поиск, hooks и
  делегирование. Sandbox read-only. Native tool events отклоняются адаптером.
  Это конфигурация прототипа, не замена отдельной OS-изоляции для недоверенного
  трафика; перед реальными диалогами нужен отдельный сервисный пользователь.
- Лимит входа/выхода 2 MiB, один запрос одновременно на экземпляр адаптера.
  При занятости — `CODEX_BUSY`; при таймауте уничтожается группа процессов.
- Автоматических повторов, API fallback и повторного исполнения инструментов нет.
  Ошибки CLI обезличены; stderr и ответ модели не пишутся в логи приложения.
- Ephemeral отключает сохранение сессий CLI. Пустые временные каталоги остаются
  для стандартной очистки ОС; адаптер не выполняет удаления файлов.

## Полный промпт: проверка на dev 27.09.2026

`backend/scripts/mila-codex-full-prompt.js` запускает настоящий `runDialog` с
Codex-провайдером, текущей версией промпта, каталогом, базой знаний и разрешёнными
инструментами чтения. Номер тестировщика поступает только через stdin. История,
состояние диалога и журнал инструментов существуют только в памяти процесса.
PostgreSQL подключается только к `loyalpro_test` с `default_transaction_read_only=on`.
Салон берётся из серверной конфигурации; при отсутствии настройки допустим только
единственный салон тестовой БД. Создание/изменение/отмена записей блокируются
белым списком обработчиков. Эскалация симулируется, диспетчер доставки не запускается.

Пример запуска без номера в аргументах команды или репозитории:

```bash
NODE_ENV=development MILA_CODEX_PROTOTYPE=true node backend/scripts/mila-codex-full-prompt.js
# Передать разрешённый тестовый номер в stdin и завершить ввод EOF.
```

Поддерживаются `--continue --case <id>` для отдельного продолжения существующего
прогона. JSON-отчёт в `/tmp/mila-codex-full-prompt-report.json` содержит только
синтетические вопросы и ответы с замаскированными именем тестировщика и номерами.
Настоящие сообщения из его переписки не загружаются. Логи сервисов внутри
отдельного процесса отключены, чтобы не сохранять идентификатор диалога и PII.

Получены 9 ответов: первый контакт, цена чистки, ботулинотерапия, адрес/часы,
эпиляция, продолжение про супругу, медицинский вопрос, prompt injection и вызов
администратора. Использован полный v1: 95 557–95 954 символа, каталог 26 035
символов. Чтение базы знаний и слотов выполнено реальными сервисами; эскалации
только тестовые. Ответ по слоту не создаёт бронирование. Это проверка этих девяти
сценариев, не исчерпывающая аттестация всех правил промпта.

Защиты стенда проверяет `backend/agent-codex-full-prompt.test.js`: запрет реальных
write-handler'ов, изоляция салона и тестового номера, симуляция эскалации,
передача чтений и маскирование имени. Проверено 6 тестов стенда и 23 теста
Codex-адаптера; UI не менялся, браузерная проверка не выполнялась.

## Воспроизведение сообщений с прода за 26 сентября

`backend/scripts/mila-codex-production-replay.js` читает только нужный салон и
московские сутки 26.09.2026. Продовая PostgreSQL-сессия принудительно read-only.
Группы исключаются; `--media-only` отдельно проверяет фото через CLI `--image`:
HTTPS-загрузка без редиректов, проверка адреса, лимит 8 MiB, проверка PNG/JPEG,
приватный временный файл. Изображение не выводится в отчёт или чат.
Серия входящих с паузой до 5 секунд объединяется в один ход; все входящие
сообщения серии учитываются. В историю попадают только предшествующие сообщения,
до 20 на ход. Старые ответы используются как история, не как эталон ответа.

Телефоны, фамилии, контакты и ссылки в транскрипте обезличиваются перед моделью.
Личное имя из карточки остаётся только в памяти процесса для корректного
обращения/контекста промпта и маскируется в отчёте. Данные исходных клиентов
НЕ заменяются данными владельца: иначе подтверждение реального визита давало
ложное «у вас нет записи». Будущие относительно исходного хода записи берутся
из снимка продовой БД, с фильтром времени создания; ID записей синтетические.
Это не полное восстановление исторического состояния CRM: поздние отмены,
переносы и актуальная занятость могут отличаться от состояния в момент сообщения.
Последние 10 прошлых визитов также берутся из снимка продовой БД. Не загруженные
исторические бонусы/абонементы возвращают явную недоступность, а не данные владельца.

Опциональный `--allow-test-booking` допустим только после разрешения владельца
создавать записи на его тестовый номер. Исполнитель принудительно подставляет
номер из stdin и существующее имя его карточки, сохраняя стандартные guards
create_booking. Прошедшее/слишком близкое время запрещено по реальным часам.
Одна попытка реального создания на дневной прогон; приватный файл с `wx`
блокирует повторы после перезапуска. Только транзакция создания получает
отдельное writable-подключение к **dev**-БД для штатной идемпотентности/журнала.
Создание в YClients реально и может запустить штатные события интеграций;
`send_sms=false` задаёт существующий сервис. Отмена, перенос и цепочка записей
не разрешены этим флагом. Эскалация симулируется, диспетчер отправки не запускается.

Запуск (разрешённый тестовый номер передаётся через stdin):

```bash
NODE_ENV=development MILA_CODEX_PROTOTYPE=true node backend/scripts/mila-codex-production-replay.js --allow-test-booking
node backend/scripts/mila-codex-replay-report.js
```

`--continue` продолжает незавершённые кейсы; `--continue --rerun --case <id>`
повторяет конкретный кейс, заменяя его строку в отчёте. Барьер реальной записи
при этом сохраняется. JSON/Markdown-отчёты хранятся приватно в `/tmp` и не
содержат исходных номеров/ФИО. Первоначальный прогон с неверным контекстом
владельца сохранён отдельно и исключён из итогового сравнения.

Тесты: `agent-codex-production-replay.test.js` — обезличивание, границы суток,
разделение диалогов, объединение серий, отсутствие будущих ответов в контексте,
автор предыдущего сообщения и принудительная подстановка разрешённого номера
и имени при создании записи.

Итог дневного replay: 65 личных текстовых сообщений и одно фото из 24 диалогов
составили 60 ходов; 7 групповых сообщений исключены. Получено 60 ответов без
ошибок запуска. Было 14 симулированных эскалаций и 4 хода с ошибками инструментов;
реальных записей не создано. Медиана ответа 9,889 с, максимум 46,363 с.
Найдены неуместное упоминание внутренних инструкций (D11-T02) и три возврата
к общей фразе защитного механизма (D06-T02, D10-T04, D10-T05). Это результат
проверки, а не подтверждение готовности интеграции к продакшену. Итоговый
обезличенный отчёт: `/tmp/mila-codex-production-2026-09-26-complete-qa.md`.
Проверки: 33 теста в трёх целевых наборах; UI не менялся, браузер не проверялся.
