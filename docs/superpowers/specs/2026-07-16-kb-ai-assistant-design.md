# База знаний — ИИ-ассистент (чат по статьям)

**Дата:** 2026-07-16
**Статус:** дизайн, ожидает утверждения
**Автор:** brainstorm с пользователем

## Проблема

На странице «База знаний» есть каталог статей и typeahead-поиск. Хочется чат-ассистента,
который на вопрос сотрудника даёт **связный ответ на естественном языке**, построенный
**строго на статьях из нашей БД** — без выдумок и без платного Claude/OpenAI.

## Ключевые решения (по итогам обсуждения)

1. **Тип ответа:** генеративный (RAG), а не просто список статей.
2. **Где LLM:** бесплатный облачный API (не локально). Провайдер — **Google Gemini 2.5 Flash**.
   Схема **dual-key**: основной ключ из проекта БЕЗ биллинга (бесплатный тариф, ~10–15 RPM,
   1500 запросов/день, только Flash/Flash-Lite), резервный — ключ из проекта `periaiassistent`
   (с картой, платный). Запрос идёт на free-ключ; при `429` (лимит исчерпан) ретраится на
   paid-ключ. Free-лимит восстанавливается сам (RPM — через минуту, RPD — на следующий день),
   и основным снова становится бесплатный ключ.
   **Важно:** на одном ключе «сначала free, потом paid» невозможно — как только на проекте
   Google включён биллинг, бесплатный тариф на нём исчезает и всё тарифицируется с первого
   токена. Поэтому нужны именно два ключа из двух разных Google-проектов.
   Стоимость платного резерва мала: `gemini-2.5-flash` — доли копейки за RAG-запрос.
3. **Аудитория:** только сотрудники (owner/admin/specialist) на staff-фронте. Мобильных
   клиентов пока НЕ трогаем (YAGNI).
4. **Retriever:** уже готов — существующий полнотекстовый поиск Postgres по `kb_articles`.
   Векторная БД / эмбеддинги НЕ нужны (объём базы — десятки/сотни статей на салон).

## Архитектура (RAG-поток)

```
Вопрос сотрудника (POST /api/kb/ask { question })   ← роутер kb монтируется на /api/kb
  1. RETRIEVE: to_tsquery('russian', ...) по kb_articles WHERE salon_id = req.user.salon_id
              AND is_published, ORDER BY ts_rank DESC LIMIT 4
              (переиспользуем buildPrefixTsQuery / логику из articles-поиска)
  2. GUARD:   если ничего не нашли → сразу ответ «В базе знаний нет статей по этому вопросу»,
              LLM НЕ вызываем (экономим лимит).
  3. BUILD:   контекст = конкатенация [ "### {title}\n{body}" ] найденных статей,
              обрезка по бюджету символов (напр. ~12k, чтобы влезть в контекст модели).
  4. PROMPT:  system: "Ты ассистент базы знаний салона. Отвечай ТОЛЬКО по тексту статей ниже.
              Если ответа в тексте нет — честно скажи 'В базе знаний нет ответа на этот вопрос'.
              Ничего не выдумывай. Отвечай кратко и по-русски."
              user: "СТАТЬИ:\n{context}\n\nВОПРОС: {question}"
  5. CALL:    fetch к Gemini API на free-ключ. При 429 (лимит) → ретрай на paid-ключ.
              Таймаут + graceful-ошибка. Оба недоступны → деградация к показу статей.
  6. RESPOND: { answer, sources: [{id, title, category_id}] }
  7. LOG:     запись в kb_chat_logs (вопрос, ответ, id статей).
```

## Компоненты

### 1. БД — новая таблица (migrations.js, IF NOT EXISTS)
```sql
CREATE TABLE IF NOT EXISTS kb_chat_logs (
  id           SERIAL PRIMARY KEY,
  salon_id     INTEGER NOT NULL REFERENCES salons(id) ON DELETE CASCADE,
  user_id      INTEGER REFERENCES users(id) ON DELETE SET NULL,
  question     TEXT NOT NULL,
  answer       TEXT NOT NULL DEFAULT '',
  source_ids   INTEGER[] NOT NULL DEFAULT '{}',
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS kb_chat_logs_salon_idx ON kb_chat_logs (salon_id, created_at DESC);
```
Назначение: отладка, аналитика «что чаще спрашивают», ловля вопросов без ответа (пробелы в базе).

### 2. Сервис — `services/kb-assistant.js`
- `retrieveArticles(salonId, question, limit=4)` — SQL-поиск, возвращает статьи. (тонкая обёртка/переиспользование существующей логики поиска)
- `buildPrompt(question, articles)` — **чистая функция** (без БД/HTTP), собирает system+user, обрезает контекст по бюджету. Юнит-тест в `kb-assistant.test.js`.
- `callLLM(prompt)` — HTTP к Gemini. Сначала free-ключ; на `429`/quota-ошибке ретрай на paid-ключ. Читает `KB_GEMINI_KEY_FREE` / `KB_GEMINI_KEY_PAID` / `KB_LLM_MODEL` из config.js. Таймаут ~20с. Оба ключа упали → бросает ошибку, которую `ask()` превращает в деградацию к статьям.
- `ask(salonId, userId, question)` — оркестратор: retrieve → guard → build → call → log → `{answer, sources}`.

### 3. Роут — `routes/knowledge-base.js`
- `POST /ask` с `readAny` (та же авторизация, что и у `/articles`).
- Валидация: `question` непустой, длина ≤ 500 симв. (анти-абьюз лимита).
- Скоуп строго по `req.user.salon_id`.
- (Опц.) простой rate-limit: не чаще N запросов/мин на пользователя — защита бесплатного лимита API.

### 4. Config (config.js)
```
KB_GEMINI_KEY_FREE = process.env.KB_GEMINI_KEY_FREE || ''  # проект без биллинга (основной)
KB_GEMINI_KEY_PAID = process.env.KB_GEMINI_KEY_PAID || ''  # ключ из periaiassistent (резерв)
KB_LLM_MODEL       = process.env.KB_LLM_MODEL       || 'gemini-2.5-flash'
```
Ключи хранятся в env бэкенда LoyalPro (не в git). Paid-ключ — тот же `GOOGLE_API_KEY`
(AIza…) из `/root/PeriAiAssistent/.env`, скопировать значение в `KB_GEMINI_KEY_PAID`.
Логика ключей:
- оба пустые → эндпоинт 503 «ассистент не настроен» (не падает);
- задан только paid → работаем сразу на платном (без free-ступени);
- заданы оба → free первым, paid по fallback на 429.

### 5. Фронт — `frontend/js/pages/knowledge-base.js`
- Кнопка/панель «Спросить ассистента» на странице База знаний.
- Простой чат: поле ввода → отправка на `/ask` через `core/api.js` → показ ответа + карточки-ссылки на статьи-источники (клик открывает статью).
- Переиспользуем стили popup/typeahead, недавно сделанные. Состояние загрузки + обработка ошибки.

## Обработка ошибок

- Нет ключа API → 503, фронт показывает «ассистент недоступен».
- LLM таймаут/лимит исчерпан → ответ-заглушка «Не удалось получить ответ, попробуйте позже» + всё равно показываем найденные статьи-источники (деградация к поиску).
- Retrieve пусто → «В базе знаний нет статей по этому вопросу», LLM не зовём.

## Тестирование

- `kb-assistant.test.js` — юнит-тесты чистых функций: `buildPrompt` (обрезка контекста, экранирование), парсинг ответа LLM, guard-ветка при пустом retrieve, **fallback free→paid по 429** (HTTP мокается: free возвращает 429 → ожидаем вызов paid; оба 429 → деградация). Без реальной сети.
- Ручная проверка в браузере (Playwright MCP) на dev-сервере.

## Приватность

Текст найденных статей уходит на сервер Gemini. Допустимо: база знаний = регламенты/инструкции/
скрипты, НЕ персональные данные клиентов. Логи запросов остаются у нас в `kb_chat_logs`.

## Явно вне scope (YAGNI)

- Мобильный клиентский чат.
- Векторный поиск / эмбеддинги.
- История диалога (multi-turn) — каждый вопрос обрабатывается независимо. Можно добавить позже.
- Стриминг ответа — сначала обычный запрос-ответ.
