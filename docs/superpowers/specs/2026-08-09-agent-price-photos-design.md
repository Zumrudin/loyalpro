# Фото прайс-листа по направлениям услуг (Мила)

Дата: 2026-08-09
Статус: дизайн утверждён, к реализации

## Задача

Клиент просит прайс. Сегодня у Милы есть только каталог услуг в промпте — она называет
цены текстом. Для направления с десятками позиций (лазерная эпиляция по зонам,
инъекции по препаратам) это либо портянка, либо — что хуже — одно число, взятое как
граница диапазона: инцидент 2026-08-01 (пациенту-мужчине названы 19 000 ₽ вместо
29 900 ₽) ровно про это.

Салон уже держит свёрстанные прайс-листы картинками. Нужно, чтобы Мила отправляла их
клиенту по запросу — по конкретному направлению, а не «всё сразу».

## Границы поведения (решение салона)

Четыре исхода, и путать их нельзя:

1. **Названо направление** («прайс на эпиляцию», «сколько стоит лазерная эпиляция»,
   «пришлите цены на инъекции») → фото прайса этого направления + вопрос, какая
   зона/услуга интересует. Цену числом в этот момент не называем.
2. **Названа конкретная услуга** («сколько стоит биоревитализация Revi Silk») → как
   сейчас: точная цена из каталога с учётом мастера и мужского прайса. Фото НЕ шлём.
3. **Прайс всей клиники без направления** («пришлите прайс», «сколько у вас всё
   стоит») → сначала уточняющий вопрос о направлении. Клиент настаивает на «всём
   сразу» → ссылка на прайс на официальном сайте.
4. **Прайса нет** (фото не загружены либо канал не умеет файлы) → ссылка на сайт +
   предложение назвать конкретную услугу, цену которой Мила скажет точно. Причину
   («канал не умеет файлы») клиенту не объясняем.

Дополнительно:

- Фото уходят все, что загружены в узел, в заданном админом порядке; за один вызов
  инструмента — РОВНО одно направление (клиент назвал два — два вызова, суммарно не
  больше 10 файлов на ход).
- Повторный запрос той же категории в том же диалоге — шлём снова. Клиент мог
  потерять картинку в ленте, и «я уже присылала выше» его не устраивает. Дедуп
  только технический, в пределах ОДНОГО хода.
- Фото загружено на направление, спрашивают про подкатегорию → берём родительское
  (подъём по дереву). Салон не должен дублировать один лист в каждую подкатегорию.

## Архитектура

### 1. Данные и админка

**Таблица `agent_price_photos`** (`migrations.js`, недеструктивно, как всё в проекте):

```
id, salon_id,
yc_category_id  INTEGER NULL,
subcategory_id  INTEGER NULL REFERENCES agent_service_subcategories(id) ON DELETE CASCADE,
file_url, file_name, mime_type, byte_size,
display_order, created_at, updated_at
```

- CHECK: заполнен РОВНО ОДИН из `yc_category_id` / `subcategory_id` — узел дерева
  адресуется однозначно, и «фото ничьё» невозможно.
- Индексы `(salon_id, yc_category_id)` и `(salon_id, subcategory_id)`.
- Каскад от подкатегории намеренный (в отличие от `ON DELETE SET NULL` у истории
  напоминаний): удалили подкатегорию — её прайс не имеет смысла хранить, форензики
  тут нет.

**Файлы** — паттерн портфолио: `multer.memoryStorage()` (id строки нужен в имени),
кап 5 МБ, только `image/jpeg|png|webp`. Путь
`frontend/uploads/pricelist_<salonId>_<c|s><nodeId>_<ts>.<ext>`, раздаётся уже
существующим `express.static` фронтенда. Удаление — через `safeUnlink`
(глотает ENOENT, работает только по `/uploads/...`).

**PDF в v1 не поддерживаем.** Chatpush отправил бы его документом, а не картинкой;
задача сформулирована про фото. Добавляется отдельно, если понадобится.

**Ссылка на сайт** — новая колонка `agent_settings.price_list_url VARCHAR(500)`,
отдаётся и принимается существующими `GET/PUT /api/agent/settings`. Детерминированное
поле, а не статья базы знаний: КБ модель может не запросить, и запасной путь молча
не сработает.

**API** (`routes/agent-settings.js`, `requireRole('owner','admin')`):

- `GET /api/agent/price-photos` → все фото салона одним запросом (дерево услуг и так
  грузится целиком, второй круг запросов не нужен);
- `POST /api/agent/price-photos` — multipart `file` + `ycCategoryId` ИЛИ
  `subcategoryId`; кап 10 фото на узел;
- `PUT /api/agent/price-photos/reorder` `{items:[{id,displayOrder}]}` — объявить
  ДО `/:id`, иначе path-матчер поймает «reorder» как id (та же готча, что у
  подкатегорий и портфолио);
- `DELETE /api/agent/price-photos/:id` — строка + файл.

**UI** — `frontend/js/pages/agent-services-catalog.js`: у каждой категории и
подкатегории в дереве кнопка `🖼 Прайс (N)` → модалка с сеткой миниатюр, загрузкой
нескольких файлов, удалением и стрелками ↑↓ для порядка. В шапке страницы — поле
«Ссылка на прайс на сайте». Обязательно бампнуть `?v=` у изменённых js-файлов:
без этого правка не доезжает до браузеров администраторов.

### 2. Путь Милы: инструмент и доставка

**Чистый модуль `services/agent/price-list.js`** (без БД и HTTP, юнит-тестируемый):

- `nodeKey(node)` → `c<ycCategoryId>` / `s<subcategoryId>` — стабильный идентификатор
  узла, общий для блока промпта и аргумента инструмента;
- `resolvePhotos(key, index)` — фото самого узла, а при их отсутствии подъём по
  `parent_id` до первого предка с фото (у подкатегории `yc_category_id` — якорь всего
  поддерева, поэтому корень достижим всегда). Возвращает `{node, photos, inheritedFrom}`;
- `renderPriceListBlock(nodes)` — текст блока промпта с ДЕТЕРМИНИРОВАННОЙ сортировкой:
  любой «плавающий» порядок ломает префикс-кэш провайдера.

**Блок промпта «ПРАЙС-ЛИСТЫ В КАРТИНКАХ»** — в кэшируемый префикс, сразу за блоком
каталога услуг. Перечисляет только узлы с СОБСТВЕННЫМИ фото (`c12|Лазерная эпиляция`):
раскрывать наследование в блок значило бы раздуть список подкатегориями, а если модель
всё же назовёт ключ подкатегории — инструмент поднимется вверх сам.

**Инструмент `send_price_list({ category })`** — сам НИЧЕГО не отправляет:

1. резолвит ключ → узел → фото (с наследованием); записи, у которых файла нет на
   диске, отбрасывает ЗДЕСЬ, а не при отправке — иначе Мила пообещает прайс, которого
   не будет;
2. проверяет канал: файлы Chatpush умеет только в `whatsapp | tdlib | max`. Для этого
   в `toolCtx` добавляется `channel` (сейчас там `dialogKey/clientPhone/clientName/nowMs`);
3. дедуп в пределах хода и кап 10 файлов — через буфер `toolCtx.attachments`; повторный
   вызов той же категории → `already_attached:true`;
4. возвращает `{attached:true, category:'Лазерная эпиляция', photos:2}` либо
   `{attached:false, reason:'no_photo'|'channel_unsupported', price_list_url:'…'}`;
5. **не входит в `SIDE_EFFECT_TOOLS`** — ход остаётся выбрасываемым при входящем
   сообщении во время прогона, и защита от дубль-ответов на серию продолжает работать.

**Оркестратор** отдаёт буфер как `res.attachments`. Буфер создаётся ВНУТРИ попытки,
поэтому черновик, выброшенный перегенерацией, уносит вложения с собой автоматически —
отдельной чистки не нужно.

**Диспетчер**: отправка вложений живёт ВНУТРИ `deliverReplies`, после цикла текста.
Это принципиально. Веток, где реплики модели намеренно НЕ доставляются, уже пять
(`alreadyEscalated`, `falseSuccess`, провал брони без переигровки, `silent`,
устаревший rerun-черновик), и файл рядом с любой из них рано или поздно забыли бы —
фото ушло бы к погашенной лжи. Каждый файл: `chatpush.sendFile` → персист в «Чат» для
WhatsApp (`msgType:'image'`, `authoredBy:'agent'`) → лог с `delivery=<id>`.

Порядок — сначала текст Милы, потом картинки; промпт это фиксирует, чтобы она не
писала «во вложении выше».

Подпись к файлу не отправляем: текст идёт отдельной репликой, и журнал авторства для
файла не нужен (эха с текстом не будет).

### 3. Правила промпта

Одно правило рядом с блоком прайсов, с четырьмя исходами из раздела «Границы
поведения» выше, плюс два запрета:

- **не пересказывать содержимое фото и не называть цены «с картинки»** — модель их
  физически не видит; выдуманная цена по прайсу это тот же класс, что инцидент
  2026-08-01 (мужской прайс) и 2026-08-06 (выдуманный адрес клиники). Цены — только
  из блока каталога;
- **не отправлять прайс по своей инициативе** — только на запрос клиента. Инициативная
  приписка адреса 06.08 началась ровно с этого.

Формулировки связываются с кодом тестом в `agent-system-prompt.test.js` (как
`OPERATOR_MARK` и образец приветствия): блок и правило не должны молча разъехаться.

### 4. Деградация и память

Везде fail-open, ход не теряется:

- сбой сборки блока прайсов → блока нет, инструмент остаётся в реестре, ключей у
  модели нет → поведение ровно сегодняшнее;
- `sendFile` упал на одном файле → WARN, остальные уходят; текст уже доставлен;
- инструмент регистрируется всегда — и в `catalogMode`, и в legacy.

**Память между ходами.** Новый инструмент ОБЯЗАН получить экстрактор в
`tool-memory.js`: реестр `tools/index.js` связан с этим файлом тестом, и новый
инструмент без экстрактора и без скипа роняет сьют. Строка журнала — «отправила
прайс-лист по направлению «Лазерная эпиляция» (2 фото)». Это же чинит «пришлите ещё
раз» на следующем ходу: модель видит, что уже слала.

## Тесты

- `agent-price-list.test.js` — чистый модуль: ключи узлов, подъём к родителю,
  приоритет собственных фото над родительскими, дедуп категории в пределах хода,
  кап 10, детерминизм блока;
- `agent-system-prompt.test.js` — блок присутствует, правило связано с ключами;
  блок ДЕТЕРМИНИРОВАН (одинаковый вход → байт-в-байт одинаковый блок). Инвариант
  «промпт без блока — префикс промпта с блоком» здесь НЕ применяется: блок стоит
  в середине промпта, сразу за каталогом услуг, а не в волатильном хвосте;
- `agent-tool-memory.test.js` — экстрактор нового инструмента;
- тест диспетчера — вложения уходят ТОЛЬКО вместе с доставленными репликами
  (погашенный `falseSuccess` и выброшенный черновик фото не шлют);
- тесты маршрутов — валидация загрузки: тип, размер, кап на узел, ровно один из
  двух id;
- живая проверка `scripts/agent-price-photo-e2e.js` — реальный резолв узла и сборка
  вложений, `sendFile` застаблен (реального сообщения никому не уходит).

## Чего фича НЕ делает

- не читает цены с картинки — цены только из каталога промпта;
- не поддерживает PDF;
- не покрыта сторожем доставки (`agent_reply_deliveries` повторяет только текст):
  потерянная доставка картинки останется незамеченной. Текст-подводка при этом уходит
  штатно и сторожом прикрыт;
- не рассылает прайсы инициативно;
- не работает в SMS / Telegram-боте / notify — там сразу ссылка на сайт.
