# База знаний — живой typeahead-поиск

**Дата:** 2026-07-16
**Ветка:** `feature/knowledge-base`
**Статус:** утверждён

## Проблема

Пользователь сообщает «поиск не работает»: при вводе текста в строку поиска Базы
знаний «вообще ничего» не появляется в ожидаемом виде.

### Диагностика (выполнена)

- **Бэкенд исправен.** Реальный SQL (`GET /api/kb/articles?q=`) находит статьи и
  через `plainto_tsquery('russian', …)`, и через `ILIKE`; `ts_rank` и `ts_headline`
  (подсветка) работают. В логах ошибок поиска нет.
- **Фронтенд подключён верно.** Роутер (`nav.js:35`) вызывает `loadKnowledgeBase()`,
  слушатель `input` навешивается в `kbBindOnce()`, helper'ы `kbEsc/kbSnippet/kbMarkdown`
  определены и загружены в правильном порядке (`kb-markdown.js` до `knowledge-base.js`).
- **Настоящая суть задачи — не баг, а UX + интеллектуальность поиска:**
  1. Результаты выводятся **в теле страницы** (заменяют список папок/статей), а не
     компактным выпадающим окном под строкой поиска.
  2. `plainto_tsquery` матчит **целые слова**: пока слово не допечатано, FTS не
     срабатывает; спасает только медленный `ILIKE`-подстрочник. Для «поиска по мере
     набора» это ощущается как «не работает».

## Решение

Переделать поиск в быстрый **выпадающий typeahead** с **префиксным** полнотекстовым
поиском (морфология сохраняется). Уровень интеллектуальности: префикс + русская
морфология без новых расширений БД (GIN-индекс уже есть). `pg_trgm` (устойчивость к
опечаткам) — намеренно **не** берём (требует `CREATE EXTENSION`, на Beget managed PG
может не хватить прав).

### 1. Бэкенд — префиксный поиск

**`services/knowledge-base.js`** — новая чистая функция `buildPrefixTsQuery(q)`:

- разбивает `q` по пробелам;
- вычищает из каждого токена спецсимволы tsquery (`& | ! ( ) : * ' \` и подобные);
- отбрасывает пустые токены;
- к каждому токену добавляет `:*`, склеивает через ` & `;
- примеры: `«мани стриж»` → `мани:* & стриж:*`; пустой/мусорный ввод → `''`.

**`routes/knowledge-base.js`, `GET /api/kb/articles`:**

- вместо `plainto_tsquery` использовать `to_tsquery('russian', <prefix>)` в ветке
  фильтра, в `ts_rank` и в `ts_headline` (префикс + морфология);
- если после очистки `buildPrefixTsQuery` вернул пустую строку — ветку FTS пропустить,
  оставить только `ILIKE '%'||q||'%'` по title/body (латиница, 1 символ, спецсимволы);
- новый query-параметр `limit`: клэмп `1..100`, дефолт `100`; typeahead шлёт `8`;
- существующие `try/catch` и XSS-защита (сентинел-маркеры `@@KBH_S@@/@@KBH_E@@`)
  сохраняются без изменений.

### 2. Фронтенд — выпадающий список под строкой

**`index.html`:**

- обернуть `#kb-search` в `<div class="kb-search-wrap">` (`position: relative`);
- добавить `<div id="kb-suggest" class="kb-suggest" hidden></div>` — абсолютно
  позиционированный popup под инпутом;
- основная страница (папки `#kb-folders` + `#kb-content`) **не меняется**;
- сброс кеша: бампнуть версию `features.css` и добавить/обновить `?v=` у
  `knowledge-base.js` и `kb-markdown.js`.

**`js/pages/knowledge-base.js`** — новый обработчик `kbTypeahead()` (debounce ~180 мс),
привязанный к `input` строки поиска:

- `q.length < 2` → popup скрыт (`hidden`), запрос не шлётся;
- иначе `GET /api/kb/articles?q=…&limit=8` → рендер строк: заголовок (`kbEsc`) +
  подсвеченный сниппет (`kbSnippet`);
- клик по строке → `kbOpenArticle(id)` + скрыть popup;
- клавиатура: `↓/↑` — перемещение активной строки (класс `.active`), `Enter` — открыть
  активную (или первую), `Esc` — скрыть popup;
- клик вне `.kb-search-wrap` / `blur` (с небольшой задержкой, чтобы клик по строке
  успел сработать) → скрыть popup;
- защита от гонки: считать «последний запрос» (счётчик/токен), игнорировать ответы,
  пришедшие для устаревшего ввода;
- пустая выдача → строка «Ничего не найдено»; ошибка fetch → popup тихо скрывается;
- клик по папке (`renderKbFolders`) по-прежнему вызывает `kbRunSearch` — просмотр
  папки в теле страницы; typeahead и in-place список не конфликтуют.

**`css/features.css`:** новые стили в тон существующим `.kb-*`:

- `.kb-search-wrap { position: relative }`;
- `.kb-suggest` — абсолютный popup: фон карточки, тень, `z-index`, `max-height` +
  `overflow-y: auto`, скругление, скрыт при `[hidden]`;
- `.kb-suggest-item` (заголовок + сниппет), `.kb-suggest-item.active` / `:hover`
  (подсветка активной), `.kb-suggest-empty` (пустое состояние);
- подсветка совпадений `b` внутри сниппета — как в `.kb-card-snippet b`.

### 3. Безопасность

- Сниппеты — только через `kbSnippet()` (полное экранирование + подсветка из
  сентинел-маркеров); заголовки — `kbEsc()`. Тело статьи не может протащить HTML в
  `innerHTML`. XSS-защита из коммита `69ea445` сохраняется.

### 4. Тестирование

- Юнит-тест `buildPrefixTsQuery` (backend): многословный ввод, вычистка спецсимволов,
  пустой ввод, латиница, одиночный токен.
- Ручная проверка вживую на dev-сервере (`:3001`) через браузер: набор текста →
  выпадающий список → клик открывает статью; проверка префикса (частичное слово
  находит статью), клавиатурной навигации и закрытия по Esc/клику вне.

## Поток данных

```
ввод → debounce(180мс) → GET /api/kb/articles?q&limit=8
     → JSON articles → рендер строк popup
     → клик/Enter → kbOpenArticle(id) → GET /api/kb/articles/:id
     → статья в #kb-content, popup скрыт
```

## Границы (YAGNI)

- Без `pg_trgm` / нечёткого поиска по опечаткам.
- Без изменения схемы БД и миграций (`search_vector`, GIN-индекс уже есть).
- Без переработки просмотра папок / рендера статьи — только строка поиска и её выдача.
