# Справка об оплате медицинских услуг (КНД 1151156) — автоматическая генерация PDF

**Дата:** 2026-06-17
**Статус:** Дизайн утверждён, готов к планированию

## Цель

Автоматизировать заполнение официального бланка «Справка об оплате медицинских услуг
для представления в налоговый орган» (Форма по КНД 1151156, приложение № 1 к приказу
ФНС России ЕА-7-11/824@). Сотрудник клиники по запросу формирует готовый PDF: часть
полей подтягивается автоматически из данных проекта, часть вводится вручную.

## Контекст проекта

- **Бэкенд:** Node.js / Express, роуты в `routes/index.js` под JWT-аутентификацией,
  сервисы в `services/`. Данные клиентов и выручки синхронизированы из Yclients в
  PostgreSQL (`peri_clinic_soft`). В зависимостях уже есть `puppeteer`; добавим
  `pdf-lib` + `@pdf-lib/fontkit`.
- **Админка:** ванильный SPA (HTML/JS/CSS, без фреймворка), `frontend/index.html`,
  вкладочный интерфейс. Раздаётся статикой из `server.js`.
- **S3:** подключение уже настроено в `services/s3.js` (креды есть в проекте).

## Решения (зафиксированы при брейнсторминге)

1. **Источник данных — гибрид:** авто (ФИО клиента, сумма оплат за год, константы
   клиники) + ручной ввод недостающих полей.
2. **Способ генерации — наложение на официальный бланк** через `pdf-lib` (не
   воссоздание HTML). Сохраняет машиночитаемые штрихкоды 2690 1015 / 2690 1022.
3. **Размещение — админ-панель персонала** (вкладка в ванильном SPA), не клиентское
   мобильное приложение.
4. **Объём — одна справка по запросу** (не пакетная генерация).
5. **Шаблон хранится в S3**, метаданные и карта координат — в БД. Шаблон можно
   загружать/обновлять через loyalpro.

## Допущения

- Пустой официальный PDF-бланк предоставляет заказчик (загружается через админку).
- «Зона QR-кода» остаётся пустой (как в образце-эталоне «Агафонов А.Э. 2025»).
- Верхние 2D-штрихкоды (2690 1015 / 2690 1022) — идентификаторы формы и страницы,
  одинаковы на всех экземплярах бланка; при наложении на готовый бланк сохраняются.
- Деление суммы на код услуги «1» (обычное лечение) и код «2» (дорогостоящее) —
  ручной ввод (это налоговая классификация, а не сумма из чека).
- Карта координат привязана к версии шаблона. Обновление бланка той же вёрстки
  координаты сохраняет; принципиально другая вёрстка требует повторной калибровки
  (через редактор координат, не код).

## Поток работы

1. Сотрудник открывает вкладку «Справки», ищет клиента, выбирает отчётный год.
2. Бэкенд возвращает автозаполненные поля (ФИО, сумма за год, константы клиники) и
   пустые ручные поля.
3. Сотрудник дополняет ручные поля (паспорт, ИНН, дата рождения, деление код 1/код 2,
   номер справки, при необходимости — страница 2) и правит автозаполненные при нужде.
4. «Сформировать PDF» → бэкенд накладывает данные на активный бланк → файл скачивается.

## Компоненты

### Бэкенд

- `routes/medical-cert.js` (JWT):
  - `GET /api/medical-cert/defaults?clientId&year` → автозаполненные значения.
  - `POST /api/medical-cert/generate` → принимает все поля, возвращает PDF (буфер).
  - `POST /api/medical-cert/template` → загрузка нового бланка в S3.
  - `GET /api/medical-cert/template` → метаданные активного шаблона + URL/рендер.
  - `GET/PUT /api/medical-cert/template/coords` → чтение/сохранение карты координат.
- `services/medical-cert-pdf.js` — ядро генерации: загрузка активного бланка из S3,
  встраивание кириллического TTF через `fontkit`, отрисовка значений по координатам,
  возврат буфера PDF. Чистые функции раскладки сумм/дат по ячейкам выделены отдельно
  (тестируемы без PDF).
- Хранилище шаблона: файл бланка в S3 (через `services/s3.js`); в БД — таблицы
  `medical_cert_templates` (s3_key, версия, активность, имя, дата) и
  `medical_cert_coords` (template_id, JSON-карта координат).

### Данные полей

- **Авто:** ФИО клиента с разбивкой на Фамилия/Имя/Отчество; сумма оплат за год из
  данных выручки в БД (если по клиенту суммы нет — поле остаётся редактируемым).
- **Константы клиники** (из настроек, редактируемые): наименование, ИНН 9724060392,
  КПП 772401001, подписант «ГАДЖИЕВА ПЕРИ ИСАМУДИНОВНА».
- **Ручные:** код вида документа, серия/номер, дата выдачи, ИНН и дата рождения
  налогоплательщика, номер справки, номер корректировки, признак «плательщик=пациент»,
  суммы по коду «1» и «2», данные страницы 2 (если плательщик ≠ пациент).

### Фронтенд (админка, ванильный SPA)

- Вкладка «Справки»: поиск клиента → выбор года → форма (авто + ручные поля) →
  «Сформировать PDF» (скачивание).
- Подраздел «Шаблон»: загрузка нового бланка, просмотр, редактор координат (наложение
  сетки/значений поверх рендера бланка для калибровки без правки кода).

## Карта координат, шрифт, генерация

- Карта координат — JSON на версию шаблона. Поле описывается: `page`, `x`, `y`, тип
  (`cells` — посимвольно с `charStep` и `maxChars`; `text` — свободный с переносами;
  `digits` — даты/суммы по ячейкам), `fontSize`.
- Суммы: рубли по ячейкам + 2 ячейки копеек. Даты: ДД.ММ.ГГГГ по ячейкам.
- Шрифт: кириллический TTF, встраивается через `@pdf-lib/fontkit` (ассет в репозитории).
  Для ячеечных полей символ центрируется в клетке.
- Страница 2 добавляется только при «плательщик ≠ пациент».
- Зона QR-кода остаётся пустой.

## Обработка ошибок и валидация

- Нет активного шаблона / S3 недоступен → понятная ошибка, генерация блокируется.
- Клиент не найден / нет суммы за год → сумма редактируется вручную, генерация не падает.
- Валидация перед генерацией: длина ИНН (10/12), формат дат, числовой формат сумм,
  обязательные поля. Ошибки показываются в форме.

## Тестирование

- Юнит-тест ядра: генерация PDF с эталонными данными → извлечение текста (`pdf-parse`)
  → проверка присутствия значений на нужных страницах.
- Тесты чистых функций раскладки сумм/дат по ячейкам.
- Ручная визуальная сверка: рендер с данными образца «Агафонов А.Э. 2025» → совпадение
  с приложенным эталонным PDF.

## Вне объёма (YAGNI)

- Пакетная генерация множества справок.
- Клиентское мобильное приложение (только админка персонала).
- Хранение паспортных данных пациента в БД (вводятся вручную при формировании).
- Электронная подача справок в ФНС / генерация QR-кода верификации.
