# Мила: LLM-мост через Codex в Финляндии

Продовая Мила использует `AGENT_PROVIDER=codex-relay`: передаёт только системный
промпт, историю и схемы инструментов на HTTPS-мост. Модель закреплена как
`gpt-6-sol`, вход через существующую подписку ChatGPT. Инструменты, CRM,
tenant-проверки, история и отправка ответов выполняются штатной Милой на проде.
Мост не загружает конфиг приложения, не обращается к БД и не отправляет сообщения.
Тумблер Милы и её списки допуска переключение провайдера не меняет.

## Контракт и защиты

`POST /api/mila-codex/v1/message` принимает `{system, messages, tools, engine?}`.
`engine` — только `gpt` (по умолчанию) или `claude`, входит в HMAC тела.
Первый запускает Codex / GPT-6 Sol, второй — Claude Code / Sonnet через подписку.
Ответ: `{requestId, model, output:{text, toolCalls:[{name,arguments}]}}`.
Произвольные model/command/env/salon_id верхнего уровня запрещены. Содержимое
диалога передаётся только на stdin Codex, не в shell и не в аргументы процесса.
Каждый запрос — отдельная ephemeral-сессия без native-инструментов Codex.
Caller проверяет модель, requestId, имена и аргументы инструментов против
собственных схем. IDs tool calls формируются на caller и не разделяются между
диалогами. Мост не имеет tenant-owned хранилища: одна серверная интеграция,
авторизация которой не даёт доступа к данным других запросов.

Подпись HMAC-SHA256 связывает метод, фиксированный путь, timestamp, случайный UUID
и точные байты тела. Заголовки `X-Mila-Timestamp`, `X-Mila-Request-Id`,
`X-Mila-Signature`; окно 60 с, повтор UUID отклоняется. Секрет не менее 32 символов,
генерируется случайно, хранится только в приватных environment-файлах серверов.
HTTPS обязателен; редиректы запрещены. Ответы no-store; нет логов промптов,
ответов и секретов. Ошибки наружу обезличены.

Лимит тела и ответа 2 MiB, до 500 сообщений и 100 инструментов. Два параллельных
запроса, очередь максимум 8 с ожиданием до 20 с; 60 подписанных запросов/минуту.
Внешний nginx ограничивает частоту запросов до чтения тела приложением.
CLI: login до 10 с, генерация до 90 с; caller 125 с, nginx 130 с.
Сам транспорт не повторяет запросы. Переключение выполняет caller по правилам
ниже. При разрыве связи уже начатая
генерация может завершиться до своего таймаута; внешних инструментов у неё нет.

## Развёртывание и перенос

Отдельный сервис `mila-codex-bridge.service` слушает только 127.0.0.1:3012.
Nginx на dev публикует только точный путь API через HTTPS. `/health` доступен
локально и показывает модель, но не аккаунт или содержимое запросов.
Исходники сервиса в `/opt/mila-codex-bridge`, отдельная копия от рабочего дерева.
Unit: `backend/deploy/mila-codex-bridge.service`; конфиг `/etc/mila-codex-bridge.env`
с правами 0600, содержит PATH, HOME, CODEX_HOME, MILA_CODEX_BIN,
MILA_CODEX_RELAY_SECRET. Требуется установленный и авторизованный CLI 0.157.1.
Сервис использует существующую локальную авторизацию; файловая система read-only,
кроме приватного tmp и каталога Codex. Директории приложения/CRM скрыты unit'ом.
Это не отдельная машина: квота подписки и каталог авторизации пока общие с Codex
на деве. Самостоятельный сервер должен иметь отдельного сервисного пользователя
и обычный вход владельца подписки через Codex, без копирования ключей в репозиторий.

На caller задаются `AGENT_PROVIDER=codex-relay`,
`MILA_CODEX_RELAY_URL=https://dev.zumrudin.ru/api/mila-codex/v1/message`,
`MILA_CODEX_RELAY_SECRET`. У prod не требуется ни CLI, ни вход ChatGPT.
Для будущего переноса поднять тот же сервис с HTTPS на новом хосте, проверить
синтетический tool-cycle, поменять URL/секрет на caller и перезапустить только
Милу. Для версии с ручным переключением нужны две добавочные таблицы (ниже).

Откат: вернуть предыдущий AGENT_PROVIDER (`polza`) и перезапустить процесс Милы.
Старый провайдер и его секреты сохраняются. Переключение не меняет enabled/mode
в agent_settings. Не включать одновременно dev и prod для одного диалога.

## Резервные модели и настройки (развёрнуто 27.09.2026)

- GPT вернул ошибку генерации, пустой/невалидный ответ либо достиг CLI-таймаута:
  caller повторяет только LLM-шаг через `engine=claude`. Все результаты ранее
  выполненных инструментов остаются в запросе, инструменты заново не запускаются.
- Сетевой отказ, таймаут caller, недоступный/перегруженный мост, отказ подписи или
  ошибка прокси: сразу «Польза», без ещё одной попытки на том же мосте.
- Ошибка Claude после GPT либо после ручного выбора Claude: «Польза».
- Отказ «Пользы»: состояние `error`, штатная обработка ошибки Милой, без цикла.
  Ошибки валидации входного запроса не запускают цепочку.
- Резерв сохраняется для салона до ручного выбора. Автоматического возврата нет.
  В ручном режиме защита от сбоев тоже работает. Уже выполняющийся запрос может
  завершиться на прежней модели; последующие используют актуальный выбор.

`providers/resilient.js` используется основным оркестратором и followup-worker.
`getProvider()` оставлен для совместимости скриптов; tenant-aware путь —
`getProviderForSalon(salonId)`. GPT и Claude имеют отдельный лимит caller 125 с.
В управляемом канале «Польза» отключены повторные попытки SDK и адаптера:
60 с основная модель, 20 с существующий запасной маршрут Polza. Напоминания ждут
до 360 с, аренда 480 с (вместо 90/180), чтобы резервная цепочка укладывалась в аренду.

Claude: `claude auth status` должен подтвердить `authMethod=claude.ai`.
CLI запускается в пустом временном cwd, `--safe-mode`, без инструментов, MCP,
настроек пользователя, skills и сохранения сессии. Отладочный вывод направлен в
`/dev/null`, история промптов выключена. Ключи API/CRM не передаются в окружение.
Промпт и диалог — только stdin; структурный ответ повторно валидируется на caller.
Псевдоним модели `sonnet` выбирает Sonnet текущей подписки, в протоколе его
стабильный идентификатор — `claude-sonnet`.

### Хранение и UI

Миграция в `backend/migrations.js` добавляет `agent_model_routing` (PK `salon_id`)
и `agent_model_notice_reads` (PK `salon_id,user_id`). Нет backfill или изменений
существующих строк; новые таблицы требуют кратких schema/FK locks, сканирования
таблиц с диалогами нет. До первого переключения используется `AGENT_PROVIDER`.
Состояние содержит канал, revision, последнюю ответившую модель, здоровье и
последний автоматический переход без диалогов/персональных данных.
CAS по revision защищает ручной выбор от параллельных ошибок и старых ответов.

API `/api/agent/model`: GET состояние, PUT `{active,revision}` ручной выбор;
POST `/acknowledge` `{revision}` подтверждение уведомления. Только owner/admin;
salon/user берутся из JWT. Ответы no-store, ошибки обезличены, конфликт выбора 409.

«Настройки → Модель Милы»: GPT / Claude Code Sonnet / «Польза», текущая модель,
канал и результат последнего запроса. До первого ответа — «Ожидает следующего
запроса». Состояние загружается при открытии раздела и кнопкой «Обновить».
При входе owner/admin получает модальное уведомление о последнем ещё не
подтверждённом автопереходе с причиной, временем МСК и текущим состоянием.
Подтверждение индивидуально; закрытие переходом в настройки не подтверждает
уведомление. Более новый переход нельзя погасить устаревшей кнопкой.

### Порядок выпуска и откат

1. После отдельного разрешения обновить изолированную копию моста на dev:
   `scripts/mila-codex-bridge.js`, `services/codex-bridge.js`,
   `services/agent/providers/{codex-relay-protocol.js,claude-code.js}` и его unit.
   Существующие `codex.js`, schema и instructions должны присутствовать.
   Unit допускает запись в существующий каталог Claude для авторизации CLI;
   `MILA_CLAUDE_BIN` / `CLAUDE_CONFIG_DIR` задаются только на сервере при необходимости.
2. Перезапустить только мост, выполнить подписанный синтетический Claude tool-cycle
   через публичный HTTPS. Старый caller совместим с новым мостом.
3. Применить только две новые миграции таблиц перед загрузкой нового caller.
   Старый caller совместим с добавочными таблицами. Миграции не подавляют ошибки:
   нельзя запускать новую маршрутизацию без её состояния.
4. Доставить изменения caller, API и UI, перезапустить LoyalPro; проверить UI,
   права и синтетические сбои. Не переносить посторонние изменения рабочего дерева.
5. Откат: вернуть прежние caller/API/UI, при необходимости прежний мост и unit.
   Новые таблицы оставить; удаление не нужно. В новой версии смена одного лишь env
   не отменяет уже сохранённый ручной выбор — использовать настройки либо откат кода.
