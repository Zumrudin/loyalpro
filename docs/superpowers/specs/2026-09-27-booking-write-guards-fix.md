# Защита создания и переноса записей: пункты 1, 2, 4

## Причина и результат

`create_booking` мог создать визит, даже когда обсуждался перенос существующего.
Обычный `reschedule_booking` проверял лишь присутствие времени в хвосте диалога,
а проверка активности исходной записи работала только для переноса цепочки.

Теперь общий `booking-write-guard.js` блокирует создание вместо переноса и
проверяет совпадения услуг с серверным списком существующих записей. Неизвестный
список не считается пустым. Дополнительный визит на ту же услугу требует
отдельного запроса и подтверждения с сохранением прежнего. Для другого человека
история читается отдельно через сервис текущего салона. Повтор создания уже
имеющегося идентичного визита возвращает его ID без записи в CRM.

Перенос требует согласия на конкретную дату и время из последнего предложения.
Отказ, изменённые условия, неоднозначные варианты и отрицательные предложения
не разрешают запись. Дата и время сопоставляются по Москве. Подтверждение цепочки
передаётся серверной capability на Symbol, привязанной к исходному ID, времени
и специалисту; аргументы модели не могут её подделать.

Перед обычным переносом CRM-запись также проверяется на активность и владельца.
Отменённая/удалённая запись не переносится. Повтор уже выполненного переноса
не вызывает новый PUT. Tenant scope и существующие проверки слотов сохранены.

Пункт 3 — общий останов пакета после ошибки обычного переноса — не изменён.
Существующие дубли не исправлялись; миграций и изменений схем API нет.
Внутренние вызывающие `reschedule_booking` теперь обязаны передавать раздельный
контекст предложения и согласия. Неоднозначные или неподдержанные формулировки
требуют уточнения до записи в CRM.

## Проверка

Новые регрессии воспроизведены до исправления. Команда из `backend/`:

```sh
AGENT_CATALOG_IN_PROMPT=false ./node_modules/.bin/jest agent-booking-write-guards agent-reschedule-booking agent-booking-modify agent-tools agent-chain-reschedule agent-book-chain agent-orchestrator agent-chain-confirmation agent-create-booking-slot-evidence agent-create-booking-generic agent-create-booking-name agent-slot-evidence agent-sequential-offers agent-tool-memory agent-recent-write --runInBand --silent
```

542 теста в 14 наборах прошли. Внешние изменения CRM заменены заглушками.
`git diff --check` без ошибок. Живые сообщения, создание и перенос записей
не выполнялись. Браузерные проверки не запускались: UI не меняется.

Дев-процесс `loyalpro` перезапущен по ранее выданному разрешению, без изменения
окружения. Перед запуском проверена тестовая БД `loyalpro_test`; после запуска —
PM2 `online`, HTTP 200 главной страницы и HTTP 401 защищённой ручки диалогов.
Проверки синтаксиса общего guard, create/reschedule tools и оркестратора прошли.

Откат: вернуть только изменения этого исправления и перезапустить дев-процесс;
изменений данных для отката нет. Откат возвращает описанные риски переноса.
