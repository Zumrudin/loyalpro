# Поиск ИИ в базе знаний сотрудников

Дата: 2026-11-08. Область: dev, `/api/kb/ask`.

## Поведение

- Общий вопрос о команде выбирает опубликованные статьи профильных разделов
  (специалисты, врачи, команда, сотрудники, персонал). Не ограничивается top-4.
  Вопрос с именем или конкретной процедурой идёт через общий поиск.
- Общий поиск объединяет полнотекстовый поиск по заголовку, разделу, тегам и
  содержимому с семантическим поиском по существующим kb_chunks. Метаданные
  имеют больший вес, чем случайное упоминание в тексте. Статьи объединяются
  по ID; длинная статья с несколькими чанками не занимает несколько мест.
- Из 24 кандидатов модель выбирает до 8 непосредственно полезных статей.
  Отбор может вернуть пустой список. Неизвестные ID и некорректный JSON
  отвергаются; при сбое отбора используется исходное ранжирование.
- При недоступности эмбеддингов работает полнотекстовая ветка; отсутствие
  чанков не скрывает статью, найденную по словам.
- Контекст: 24 000 символов, равная доля на статью, максимум 40 статей.
  Усечение явно передаётся модели; источники — только включённые статьи.
  Список специалистов должен содержать имена и подтверждённые специализации,
  без незапрошенных аппаратов/цен и заявления полноты при неполных данных.

## Совместимость и границы

API `{answer,sources}` и логирование прежние. Миграций и переиндексации нет.
Каждый запрос ограничен серверным salon_id и опубликованными статьями.
Внутренние статьи доступны сотрудникам, как прежде. Пациентский agent-rag
и его фильтр internal_only не изменены; используются только его чистые функции.
Поиск не вызывает YClients, не отправляет сообщения и не меняет записи/бонусы.

## Проверка и ограничения

`cd backend && npx jest kb-search kb-assistant agent-rag --runInBand --silent`

Живой read-only подбор проверяется на dev-БД loyalpro_test. Для проверки
генерации нужен PATH дев-сервиса (Node/Codex из v20.20.2), а не PATH сессии CLI.
Полноту и корректность свободного ответа всё ещё оценивает модель.
Дополнительный отбор увеличивает задержку общих вопросов; общий вопрос о
команде обходит его. Векторы несовпадающей размерности пропускаются.
Очень большие разделы дают явно неполную подборку; пагинация ответа не добавлена.

Откат: вернуть kb-assistant.js и убрать подключение kb-search.js, перезапустить
только dev-сервис. Данные и индекс не меняются.

## Результат проверки на деве

- 78 тестов в 6 наборах прошли командой выше из backend. Случайный запуск
  Jest из корня захватил посторонние worktrees и завершился ошибками зависимостей;
  штатный запуск из backend прошёл.
- Read-only подбор + живая генерация: команда → 4 профиля со специализациями;
  Lumecca → исполнители; «убрать морщинки» → тематические процедуры;
  ипотека → нет подходящих источников. Замеры 7–32 с, не гарантия SLA.
- Перезапущен только dev PM2 loyalpro (порт 3001, loyalpro_test).
- HTTP после рестарта: команда и конкретный врач — 200 без degraded;
  без авторизации — 401, пустой вопрос — 400; поиск для отсутствующего
  салона не возвращает чужие статьи.
- Puppeteer с системным Google Chrome: страница #knowledge-base, отправка
  исходного вопроса → 4 пункта списка, 4 источника, без Lumecca и ошибки UI.
  Посторонние API-запросы страницы заблокированы при проверке.
- Прод не выкатывался. Mobile lint не запускался: мобильных изменений нет.
