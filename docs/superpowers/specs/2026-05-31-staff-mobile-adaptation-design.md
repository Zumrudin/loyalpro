# Адаптация staff-фронтенда LoyalPro под мобильные телефоны

**Дата:** 2026-05-31
**Статус:** дизайн утверждён, готов к планированию
**Компонент:** `frontend/` (staff SPA на vanilla JS, отдаётся бэкендом)

## Проблема

Веб-приложение для персонала салона (`frontend/`) не адаптировано под телефоны. На ширине `≤700px`:

1. **Навигация исчезает** — `.tb-nav` имеет `display:none` и не заменяется ничем (бургера/нижнего меню нет). На телефоне физически нельзя переключать разделы. — критично.
2. **Шапка переполнена** — логотип + статус синка + кнопка «Синхронизировать» + переключатель темы + аватар + имя + «Выйти» не помещаются в строку 52px.
3. **Настройки** — боковой sidebar (`.stg-sidebar`) не адаптирован.
4. **Таблицы** («Клиенты», «Записи») скроллятся вбок, тесные, неудобны пальцем.
5. **Паддинги/тач-таргеты** рассчитаны на мышь (`content:22px`, мелкие кнопки).

Частичный адаптив уже есть: `viewport` мета-тег, часть сеток сворачивается через `@media` (дашборд-статы, карточки сотрудников, фото-кейсы), таблицы обёрнуты в `.tw{overflow-x:auto}`, модалки `max-width:95vw`.

## Цель

Полная адаптация всех 9 разделов staff-приложения под телефоны (Дашборд, Клиенты, Записи, Сотрудники, Сегменты, Уход, Фото-кейсы, Настройки, Пользователи), без изменения десктопного вида и без регрессий на проде.

## Выбранный подход: CSS-first + точечный JS

Слой мобильных переопределений поверх существующих десктопных стилей. Никаких фреймворков и mobile-first рефакторинга разметки — в духе текущего vanilla-JS кода, минимум риска для прода, всё обратимо.

Отвергнутые варианты:
- **Mobile-first рефакторинг разметки** — переписать каркас `index.html` (1623 строки) и страницы; высокий риск регрессий на работающем проде.
- **Отдельные мобильные стили/вьюхи** — условно подгружаемый CSS или отдельные шаблоны; дублирование и двойная поддержка, оверинжиниринг.

## Дизайн

### 1. Брейкпоинты и стратегия файлов

Брейкпоинты совпадают с уже существующими в коде:
- `≤700px` — основной мобильный режим: бургер-навигация, карточки вместо таблиц, одноколоночные сетки.
- `≤480px` — мелкие донастройки (паддинги, размер шрифта шапки, полноширинные кнопки).
- `>700px` — десктоп без изменений.

Все стили — в один консолидированный блок `/* ─── MOBILE ─── */` в конце `css/base.css` (тематические — рядом в `css/features.css`). Новых CSS-файлов не создаём. Десктопные правила не трогаем, только добавляем `@media`-оверрайды. Принцип: desktop — источник истины, мобила — слой переопределений; правку можно убрать удалением блока.

### 2. Шапка и навигация (бургер + drawer)

**Шапка `≤700px`:**
- Слева — новая кнопка-бургер `☰` + логотип LoyalPro.
- Справа — только переключатель темы 🌙 и аватар.
- Переезжают внутрь drawer: текст статуса синка, кнопка «Синхронизировать», имя пользователя, кнопка «Выйти».

**Drawer (выезжающее меню слева):**
- Оверлей затемнения + панель ~80vw (max ~300px), слайд слева.
- Закрытие: тап по оверлею / Esc / выбор пункта.
- Шапка drawer: аватар + имя + роль.
- Тело: те же 9 пунктов навигации с роле-фильтром.
- Футер drawer: «Синхронизировать» (+ статус синка), «Выйти».

**Реализация:**
- HTML: кнопка-бургер в `.topbar`; блок `<aside class="mnav-drawer">` + оверлей в `index.html`.
- JS (`js/core/nav.js`): `openMenu()` / `closeMenu()`; существующая `nav(el)` дополняется авто-закрытием drawer после перехода. Пункты drawer используют те же `data-p` / `data-roles`; селектор в `applyRoleNav` расширяется, чтобы покрывать и пункты drawer (роле-фильтр работает для обоих наборов).
- CSS: на десктопе drawer и бургер скрыты; на `≤700px` — `.tb-nav` скрыт, бургер и drawer активны.

### 3. Таблицы → карточки

Затрагиваются главные широкие таблицы: «Клиенты» (`js/pages/clients.js`, рендер около строки 84) и «Записи» (`js/pages/records.js`, рендер около строки 53).

Стандартный responsive-table паттерн:
- В рендер-функциях каждому `<td>` добавляется `data-label="…"` (на десктопе игнорируется).
- CSS `≤700px`: `thead{display:none}`; `tr{display:block}` с оформлением карточки (рамка/тень/радиус/`margin-bottom`); `td{display:flex; justify-content:space-between}`; `td::before{content:attr(data-label); color:var(--t3)}` слева.
- Результат — пары «лейбл — значение» построчно в карточке. Клик по карточке открывает деталь клиента (`onclick` на `<tr>` сохраняется).
- Аватар клиента выносится в заголовок карточки; дублирующая колонка-действие «→» на мобиле убирается.
- Пагинация: кнопки крупнее, `flex-wrap`.

Второстепенные таблицы (история операций в модалке клиента, логи синка в настройках) остаются на горизонтальном скролле `.tw{overflow-x:auto}` — в карточки не превращаются (гибрид).

### 4. Формы, модалки, настройки, сетки

- **Модалки** (`.modal`, `base.css:166`): на `≤700px` — `width:100%`, прижатие к низу (bottom-sheet) или почти полноэкранно, `max-height:92vh` со скроллом, паддинг 16px. Длинные формы — в одну колонку.
- **Настройки** (`.stg-sidebar`): на мобиле боковое меню разделов → горизонтально-скроллящаяся полоса «чипов» сверху; контент раздела на всю ширину; формы в одну колонку.
- **Сетки:** добить одноколоночность где её ещё нет (`.g3` / `.g32` / `.g2`); карточки фото-кейсов на `≤480px` в 1 колонку; дашборд-статы читаемы. Дроверы сегментов (`.seg-drawer`) уже `100vw` на мобиле — оставить.
- **Тач-таргеты:** мин. высота интерактивных элементов ~40px; `.content` паддинг 22px→14px; поля ввода `font-size:16px` на мобиле (iOS Safari не зумит при фокусе).

### 5. Тестирование

MCP Playwright (без bash-скриптов — по правилам проекта):
- Эмуляция вьюпорта телефона (390×844) + проверка на 360px.
- Проход по всем 9 разделам: открыть drawer → перейти → контент читаем, нет горизонтального переполнения страницы, таблицы стали карточками.
- Модалки (создание клиента, фото-кейс), настройки, тёмная тема на мобиле.
- Регрессии десктопа: тот же набор на 1280px — без изменений.

## Критерии готовности

1. На `≤700px` навигация доступна через бургер-drawer; роли видят свои пункты.
2. Шапка не переполняется на 360px и 390px.
3. Нет горизонтального скролла страницы (кроме намеренного — внутри лог-таблиц).
4. Таблицы «Клиенты» и «Записи» отображаются карточками и кликабельны.
5. Модалки и формы юзабельны одним пальцем; iOS не зумит поля.
6. Десктоп (`>700px`) визуально не изменился.

## Вне scope

- Мобильное Expo-приложение (`mobile/`), бэкенд, API.
- Редизайн десктопа.
- Превращение лог-таблиц (история операций, логи синка) в карточки.

## Затрагиваемые файлы

- `frontend/index.html` — кнопка-бургер, разметка drawer + оверлей.
- `frontend/css/base.css` — блок `/* ─── MOBILE ─── */` (шапка, drawer, карточки-таблицы, модалки, тач-таргеты).
- `frontend/css/features.css` — мобильные оверрайды тематических компонентов (настройки, фото-кейсы) при необходимости.
- `frontend/js/core/nav.js` — `openMenu()` / `closeMenu()`, авто-закрытие в `nav()`, расширение `applyRoleNav`.
- `frontend/js/pages/clients.js` — `data-label` в рендере таблицы.
- `frontend/js/pages/records.js` — `data-label` в рендере таблицы.
