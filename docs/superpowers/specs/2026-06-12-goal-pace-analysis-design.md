# Анализ темпа в «Цели месяца» — автокомментарий специалисту

**Дата:** 2026-06-12
**Статус:** утверждено пользователем (дизайн-диалог)
**Затрагивает:** `backend/services/staff-goals.js`, `backend/staff-goals.test.js`, `frontend/js/pages/staff-dashboard.js`

## Проблема

Карточка «Цель месяца» показывает план/факт/прогноз, но не отвечает на главный
вопрос специалиста: «успеваю ли я, и сколько мне нужно делать за смену, чтобы
успеть?». Нужен автоматический комментарий-оценка темпа, раздельно по Услугам
и Товарам, обязательно с учётом графика работы (смены из `staff_schedule`).

## Решения пользователя

1. Комментарий — под каждым баром раздельно (Услуги / Товары)
2. Если укладывается — просто «в таком темпе укладываетесь», БЕЗ прогнозов
   досрочного закрытия плана
3. Если не укладывается — явно «таким темпом не уложитесь, нужно в среднем
   ₽X за смену»
4. График не синхронизирован → подсказка «Синхронизируйте график в YClients,
   чтобы видеть расчёт по сменам» (вердикт по календарному прогнозу остаётся)
5. Порог с допуском ±5%: 95–105% прогноза — «впритык» (жёлтый)
6. План уже выполнен → статистика остаётся, пишем перевыполнение
   («перевыполнение на X% — красавчик»)

## Backend

`services/staff-goals.js` — новая чистая функция (экспортируется):

```js
computePace(target, fact, forecast, workedDays, plannedDays) → pace | null
```

Правила (по приоритету):
1. `target <= 0` → `null` (фронт ничего не показывает — карточка и так скрыта)
2. `fact >= target` → `{ status: 'done', overPct }`,
   `overPct = Math.round((fact / target - 1) * 100)` (0 при ровном выполнении)
3. `plannedDays <= 0` → `{ status: 'no_schedule', ratio }` — графика нет;
   ratio = forecast/target (для вердикта по календарному прогнозу)
4. Иначе r = forecast / target:
   - r ≥ 1.05 → `{ status: 'ahead' }`
   - 0.95 ≤ r < 1.05 → `{ status: 'tight', perShiftNeeded, remainingShifts }`
   - r < 0.95 → `{ status: 'behind', perShiftNeeded, remainingShifts }`
   - `remainingShifts = plannedDays - workedDays`
   - `perShiftNeeded = Math.ceil((target - fact) / remainingShifts)`;
     если `remainingShifts <= 0` → `perShiftNeeded = null`
     (фронт покажет вердикт без цифры за смену)

Вызов: в `getGoalForStaff` результат кладётся в `goal.services.pace` и
`goal.goods.pace` (по соответствующим target/fact/forecast; workedDays и
plannedDays общие).

Unit-тесты в `staff-goals.test.js` (дописать describe `computePace`):
- target=0 → null
- fact == target ровно → done, overPct 0
- fact > target → done, overPct верный
- plannedDays=0 → no_schedule c ratio
- r = 1.05 ровно → ahead; r = 0.95 ровно → tight; r = 0.949 → behind
- perShiftNeeded: целое вверх, (target-fact)/remainingShifts
- remainingShifts=0 при behind → perShiftNeeded null

## Frontend

`goalBar()` в `staff-dashboard.js`: после строки «Прогноз: ₽N» (она
сохраняется мелким текстом) добавляется комментарий по `o.pace`:

| status | Текст (значения подставляются) | Цвет |
|---|---|---|
| done | 🎉 План выполнен — перевыполнение на {overPct}%! Красавчик, так держать! | зелёный |
| ahead | 🟢 Отличный темп! В таком ритме вы укладываетесь в план | зелёный |
| tight | 🟡 Идёте впритык: надёжнее держать в среднем ₽ {perShiftNeeded} за смену (ещё {remainingShifts} смен) | янтарный |
| behind | 🔴 Таким темпом план не закрыть: нужно в среднем ₽ {perShiftNeeded} за смену (ещё {remainingShifts} смен) | красный |
| no_schedule | вердикт по ratio (🟢/🟡/🔴 по тем же порогам, без «за смену») + серая подсказка: «Синхронизируйте график в YClients, чтобы видеть расчёт по сменам» | по ratio + серый |

Для tight/behind при `perShiftNeeded === null` (смен не осталось) — только
вердикт без цифры за смену.

Склонение «смен»: существующий `_sdPlural(n,'смена','смены','смен')` с
предлогом «ещё» → «ещё 1 смена», «ещё 2 смены», «ещё 9 смен» (без проблемы
согласования глагола «осталось/осталась»).

**Цвет прогресс-бара** приводится к тем же порогам: done/ahead — зелёный
`#13a05e`, tight — янтарный `#e8a23d`, behind/no_schedule(r<0.95) — красный
`#d23f3f` (сейчас пороги 100/80 — заменяются).

## Не делаем (YAGNI)

- Никаких прогнозов даты досрочного закрытия плана
- Никаких настраиваемых порогов
- Общий вердикт по карточке (только раздельные по барам)
- Изменений в админке «Сотрудники» (только личный дашборд)

## Критерии приёмки

1. Специалист с планом и графиком, прогноз < 95% → красный комментарий с
   ₽/смену и числом смен
2. Прогноз ≥ 105% → зелёный «укладываетесь», без цифр за смену
3. Факт ≥ план → 🎉 с процентом перевыполнения, бар остаётся
4. `plannedDays=0` → вердикт + подсказка про синхронизацию графика
5. Unit-тесты computePace зелёные, существующие тесты не сломаны
6. Цвет бара совпадает с цветом комментария
