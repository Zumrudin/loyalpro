# Каталог услуг в кэшируемом системном промпте агента (A+D)

Дата: 2026-07-27. Статус: дизайн утверждён, к имплементации.

## Проблема

Инструмент `list_services` отдаёт весь каталог (220 услуг PERI CLINIC) как JSON
с вложенным массивом мастеров у каждой услуги — ~77k символов (~26–29k токенов).
Результат попадает в `convo` и пересылается в LLM **на каждой итерации
tool-цикла внутри одного хода** (`orchestrator.js:163`, до 12 итераций,
сложная запись — 6–8). Ход записи ≈ 170k некэшированных входных токенов только
на каталог — это основной пожиратель бюджета для любой модели
(GPT: 2.5 ₽ из 2.68 ₽/ход; Gemini: 0.79 ₽).

Замер на живых данных (salon 1):

| Формат | Символы | ≈Токены |
|---|---|---|
| Текущий JSON со staff | 77 645 | ~26–29k |
| JSON без staff | 34 651 | ~13k |
| Компактный текст | 16 102 | ~6k |

~80% веса — декартов повтор `{yc_id,name,price_min,price_max}` мастеров в
каждой услуге. Важно: результат tool **не** персистится в историю диалога
(`history.js` хранит только текст), т.е. проблема живёт внутри одного хода.

## Решение

Каталог уходит из tool-результата в **компактный текстовый блок системного
промпта**, который кэшируется провайдером (Polza уже ставит `cache_control`
на system-блок). `list_services` из реестра убирается; per-master цены —
новым лёгким инструментом `get_service_masters`.

### 1. Блок каталога — `services/agent/catalog-block.js`

Чистый модуль-рендерер + общий загрузчик данных.

- Выборка данных (salon, staff_members, фильтр видимости, дерево категорий,
  `ycGetServiceCatalog`, `ycGetServiceMeta`) выносится из
  `tools/list-services.js` в общий хелпер `loadCatalogData(salonId)`
  (место: `services/agent/catalog-data.js`), чтобы tool (legacy-режим) и блок
  промпта использовали одну логику фильтров.
- Формат блока:

```
КАТАЛОГ УСЛУГ (id | название | длительность мин | цена ₽ | направление | мастера):
Мастера: 55=Аня Иванова, 66=Пери Гаджиева, ...
9536378|3D моделирование подбородка 1 ml|60|23000|Инъекционная косметология>Контурная пластика|55,66
9536382|HairFiller пептидный филлер 1ml|30|от 12000|Инъекционная косметология>Мезотерапия|66
```

- **Цена**: `price_min === price_max` → одно число; `price_max === 0 (или
  null) && price_min > 0` → `от {price_min}` (YClients-паттерн «от X»);
  иначе `min-max`. Цена в строке — агрегат по отфильтрованным мастерам
  (как сейчас в list-services).
- **id мастеров в строке** + легенда сверху: связь услуга→мастер видна сразу,
  слоты/бронь без дозапроса.
- **Санитизация**: каждое название услуги, категории и имя мастера — через
  `sanitizeLine` (названия приходят из YClients и попадают в системный промпт —
  привилегированная позиция, инъекция через название режется).
- **Детерминизм**: услуги сортируются по `yc_id`, мастера в легенде и в строках
  по id — блок байт-в-байт стабилен между запросами, иначе кэш не хитит.
  Стабильность данных даёт существующий in-memory TTL-кэш `ycGetServiceCatalog`.
- **Фолбэки**: YClients упал → строки из `services_config` (заголовки без цен);
  данных нет совсем → оркестратор работает в legacy-режиме (см. §4).
- **Guard**: блок > 40k символов → warning в лог (аномально большой салон).

### 2. Инструменты

- `list_services` убирается из реестра в новом режиме (код остаётся для
  legacy-режима).
- Новый `get_service_masters`:
  - `input_schema`: `{ service_yc_ids: number[] }` (required, 1..20).
  - Выход: `{ services: [{ yc_id, title, staff: [{ yc_id, name,
    price_min, price_max }] }] }` — персональная цена мастера
    (врач vs главврач), фолбэк на агрегат услуги.
  - Данные — из того же `loadCatalogData`.
  - Когда звать (промпт): клиент спрашивает цену у конкретного мастера;
    точная сумма при подтверждении записи, если у услуги диапазон.
- Остальные 16 инструментов без изменений.

### 3. Промпт и кэширование

- `system-prompt.js` принимает `opts.catalogBlock` (готовый текст) и вставляет
  его отдельной секцией; все правила, ссылающиеся на `list_services`
  («услуга только по list_services», сценарии), переписываются на
  «только из раздела КАТАЛОГ УСЛУГ» / `get_service_masters`.
- Тесты промпта (`agent-system-prompt`) и тест реестра инструментов
  обновляются под оба режима. Промпт защищён тестами — правила не срезать,
  только перенаправить источник каталога.
- Polza: system уже под `cache_control` (`polza.js:56-64`) — блок каталога
  автоматически кэшируется; GPT-модели кэшируют префикс автоматически.
- `providers/anthropic.js`: добавить `cache_control: {type:'ephemeral'}` на
  system-блок (сейчас кэширования нет вообще).

### 4. Фича-флаг и откат

- Env `AGENT_CATALOG_IN_PROMPT` (config.js, default off).
- Оркестратор: флаг включён и блок построился → system с каталогом + реестр
  без `list_services`, с `get_service_masters`; иначе → текущее поведение
  (list_services в реестре, промпт без каталога).
- Откат — сменить env + рестарт, без деплоя кода.

### 5. Экономика

Ход записи (~7 итераций): было ~28k × 6 ≈ 170k некэшированных токенов
каталога; станет ~6k × 7, из них итерации 2..N по кэш-тарифу → эффективно
~15–20k. ≈10× дешевле каталожной части + минус одна итерация (нет вызова
list_services). Компромисс: простые ходы теперь несут ~6k кэшированных
токенов (копейки).

## Риски

1. Смена цены в YClients инвалидирует кэш посреди диалога → один ход по полной
   цене. Приемлемо.
2. Дисциплина модели с каталогом в промпте vs tool_result — прогнать
   тест-харнесс живых сценариев на деве до включения флага по умолчанию.
3. Per-master цена не видна в строке (только диапазон) — закрыто
   `get_service_masters`.

  контроль cost_rub и cached-токенов в логах polza.
