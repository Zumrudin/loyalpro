# Админ-страница «Чат» (просмотр переписок chatpush) — дизайн

**Дата:** 2026-07-18
**Статус:** утверждён к реализации
**Режим:** только просмотр (read-only)

## Цель

Дать персоналу салона (owner/admin) страницу «Чат» в веб-интерфейсе для
**просмотра** входящих и исходящих сообщений, которые проходят через
интеграцию с chatpush. Отправка ответов и авто-обновление в этот этап
**не входят** — только чтение.

## Контекст (что уже есть)

- Таблица `chatpush_messages` (см. `backend/migrations.js`) хранит
  нормализованные сообщения: `salon_id, client_id, customer_id, channel,
  direction, external_message_id, msg_type, text, file_url, mime_type,
  sender_name, phone, chat_id, msg_ts, created_at`. Индекс
  `idx_chatpush_messages_dialog (salon_id, phone, msg_ts DESC)`.
- Вебхук `routes/chatpush-webhook.js` уже пишет входящие и исходящие
  сообщения в эту таблицу (идемпотентно, `ON CONFLICT (salon_id,
  external_message_id) DO NOTHING`).
- Сервис `services/chatpush.js` умеет отправлять сообщения — в этом этапе
  **не используется** (read-only).
- **Нет** ни одного API-эндпоинта и страницы для просмотра переписок.
- Диалоги неявно группируются по `(salon_id, phone/chat_id)` — отдельной
  таблицы conversations нет и не создаётся.

## Архитектура

Двухпанельный интерфейс мессенджера внутри существующего ванильного SPA:

- **Слева** — список диалогов (по одному на собеседника), сортировка по
  времени последнего сообщения (свежие сверху).
- **Справа** — история выбранного диалога: входящие слева, исходящие
  справа (пузыри), по возрастанию времени.
- Источник данных — существующая таблица `chatpush_messages`, всё
  скоупится по `req.user.salon_id`.
- Обновление — кнопкой «Обновить» и автоматически при открытии страницы
  и при открытии диалога. **Без фонового поллинга.**
- Ничего не отправляем и не пишем в БД — только SELECT.

## Бэкенд

Новый роутер `backend/routes/chat.js`, смонтирован в `routes/index.js`
под `/api/chat`. JWT применяется автоматически существующим guard'ом.
Доступ — роли `owner` и `admin`; `specialist` не допускается (не входит
в `SPECIALIST_ALLOWED_PREFIXES`, поэтому guard отсекает автоматически).

### `GET /api/chat/dialogs`

Список диалогов текущего салона. Группировка по `phone` (fallback
`chat_id`, если phone пуст). Для каждого диалога:

- ключ диалога (phone или chat_id),
- `channel` последнего сообщения,
- `sender_name`,
- `last_text` (текст последнего сообщения; для медиа — подпись/пометка),
- `last_direction`,
- `last_ts` (`msg_ts` последнего сообщения),
- `messages_count`,
- `client`: `{ id, name }` если `client_id` привязан, иначе `null`.

Реализация SQL: `DISTINCT ON (COALESCE(NULLIF(phone,''), chat_id))`
с `ORDER BY dialog_key, msg_ts DESC` для «последнего сообщения», плюс
агрегат `COUNT(*)` для `messages_count` (подзапрос/оконная функция).
Финальная сортировка результата — по `last_ts DESC`.

Ответ: `{ dialogs: [ ... ] }`.

### `GET /api/chat/dialogs/:key/messages`

Все сообщения одного диалога, `WHERE salon_id = $1 AND
COALESCE(NULLIF(phone,''), chat_id) = $2`, `ORDER BY msg_ts ASC`.
`:key` валидируется/экранируется (передаётся как параметр запроса, не
конкатенируется в SQL). Каждое сообщение:

- `id, direction, channel, msg_type, text, file_url, mime_type,
  sender_name, msg_ts`.

Ответ: `{ messages: [ ... ] }`.

### Обработка медиа

Для `msg_type != 'text'` показываем текст-подпись (если есть) плюс
пометку «📎 вложение (документ/фото/…)». Если есть `file_url` — даём
ссылку, с оговоркой в UI, что ссылки chatpush временные и могут
протухнуть.

## Фронтенд

- **`frontend/js/pages/chat.js`** (новый):
  - `loadChat()` — грузит `/api/chat/dialogs`, рендерит список слева.
  - `openChatDialog(key)` — грузит историю, рендерит справа.
  - локальный `_esc` для экранирования (как в других страницах).
  - экспорт функций в `window` для inline-onclick.
- **`frontend/index.html`**:
  - пункт меню `💬 Чат` с `data-roles="owner,admin"` в `#mainNav` и
    `#mnavList`.
  - блок `<div class="page" id="page-chat">` с двухпанельной вёрсткой
    (список диалогов + область истории + кнопка «Обновить»).
  - `<script src="js/pages/chat.js"></script>` перед `js/app.js`.
- **`frontend/js/core/nav.js`**: ветка `if (p === 'chat') loadChat();`
  в роутере `navTo`.
- **CSS**: используем существующие классы (`card`, `btn`, `btn-pri`,
  `empty`); добавляем небольшой блок в `css/features.css` для пузырей
  чата, списка диалогов и цветных бейджей каналов.
- Бейдж канала (WhatsApp/Telegram/MAX/…) — цветная метка рядом с
  диалогом и/или в шапке истории.

## Обработка ошибок и крайние случаи

- Пустые состояния: «Пока нет сообщений» (нет диалогов) и «Выберите
  диалог» (ничего не выбрано).
- Диалог без совпавшего клиента — показываем `sender_name`/телефон.
- Ошибка API — сообщение/тост, страница не падает.
- Всё строго скоупится по `salon_id` из JWT.
- Ключ диалога в URL — как параметр запроса, экранируется.

## Явно вне объёма (YAGNI на этом этапе)

- Отправка ответов из интерфейса.
- Фоновый поллинг / реалтайм / бейдж непрочитанных.
- Поиск по диалогам.
- Кэширование/перезаливка временных медиа chatpush в своё хранилище.
