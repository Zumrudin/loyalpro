# Фото-кейсы — редизайн (мобильный + десктоп) — Design

**Дата:** 2026-06-01
**Ветка:** feat/patient-photo-cases
**Статус:** утверждён дизайн (визуальное направление «A · Чистая клиника» + сравнение «рядом»)

## Цель

Сделать страницу «Фото-кейсы» в staff-фронте не «серой и скучной», а аккуратной, фирменной и удобной — в первую очередь на телефоне. Редизайн охватывает все три уровня: лента (L1), карточка пациента (L2), альбом визита (L3). Главный смысловой акцент — наглядное сравнение «До → После».

## Принятые решения (из брейншторма)

- **Визуальный язык — «A · Чистая клиника»:** светлые мягкие карточки со скруглением и мягкой тенью, крупные фото, фирменный градиент `--grad-a` (бирюза→синий) как акцент «результата», живые пустые состояния вместо серого текста «Нет фото».
- **Сравнение «До → После» — вариант «рядом» (side-by-side):** в альбоме сверху карточка-сравнение из двух фото с подписями ДО / ПОСЛЕ. Слайдер-шторка сознательно отложен (требует совпадения ракурсов и заметно больше JS).
- **Полный охват:** L1 + L2 + L3.
- **Тёмная тема обязана продолжать работать** — все цвета только через CSS-переменные, без хардкода фонов/текста.

## Не входит в объём (YAGNI)

- Слайдер-шторка «До/После» (отложен; можно добавить позже отдельной задачей).
- Выбор пользователем конкретных фото для сравнения (в MVP — авто-подбор, см. ниже).
- Drag-drop переупорядочивание фото, теги, фильтры.
- Изменения мобильного приложения (`mobile/`) — это staff-фронт.

## Архитектура изменений

Затрагиваются три файла. Логика навигации/загрузки не меняется — меняются разметка рендеров и стили.

- `frontend/css/base.css` — блок стилей `#page-patient-portfolio` (≈ строки 246–319) переписывается под новый язык; мобильные медиа-запросы (≈ 415–424) дополняются. **Все цвета — через существующие переменные** `--a --grad-a --card --bg --bd --t1 --t2 --t3 --r --sh` и т. п.
- `frontend/js/pages/patient-portfolio.js` — обновляется HTML-разметка в `_ppRenderFeed` (L1), `_ppRenderPatient` (L2), `_ppRenderAlbum` (L3): новые классы/обёртки, карточка-сравнение, дропзоны, перенос «Удалить альбом» в меню ⋯. Обработчики (загрузка, лайтбокс, заметки, комментарии, удаление) сохраняются — меняются только селекторы при необходимости.
- `backend/routes/patient-portfolio.js` — две точечные правки данных (см. «Данные и интеграция»). Не трогаем загрузку/удаление/обработку фото.

### Цветовая семантика стадий

| Стадия | Акцент |
|---|---|
| `before` (ДО) | нейтральный — серый чип счётчика (`--bg`/`--t3`) |
| `in_progress` (В процессе) | нейтральный |
| `after` (ПОСЛЕ) | фирменный: верхняя полоса `--grad-a` (3px) + бирюзовый чип счётчика (`--as`/`--a`) |

«После» визуально выделена как «результат» — это направляет взгляд.

## L1 — Лента (`_ppRenderFeed`)

- Строка поиска и кнопка «+ Создать альбом» → компактная панель: инпут с иконкой 🔍 на фоне `--bg`, кнопка с заливкой `--grad-a`.
- Плитки альбомов: карточка `--card`, скругление `var(--r)`, тень `var(--sh)`, тонкая рамка `--bd`. Превью-фото шире и выше (≈ полная ширина карточки, высота ~120–160px, `object-fit:cover`). Под фото — имя пациента (жирно, `--t1`), мета (`--t3`): дата · N фото · комм.
- **Бейдж «До·После»** в правом верхнем углу превью — только если у альбома есть фото и в стадии `before`, и в стадии `after`. Заливка `--grad-a`, белый текст.
- Состояние «нет альбомов» — дружелюбный блок с иконкой и подсказкой (не голый серый текст).
- Сетка: десктоп `repeat(auto-fill, minmax(220px,1fr))`; ≤480px — 1 колонка.

## L2 — Карточка пациента (`_ppRenderPatient`)

- **Шапка пациента:** аватар-кружок с инициалами и заливкой `--grad-a`, имя (`--t1`), под ним телефон и «N альбомов» (`--t3`).
- **Курсы лечения** → горизонтальный ряд чипов: активные курсы — чип `--as`/`--a` со скруглением 20px; «+ Курс» — нейтральный чип. (Заменяет вертикальный сайдбар `pp-courses` на мобильном; на десктопе допускается тот же ряд чипов сверху, сетка `pp-grid` упрощается до одной колонки контента.)
- **Альбомы** → ряды-карточки: слева миниатюра (62×62, скругление), справа дата (жирно), специалист · N фото, и `↳ Курс` цветом `--a`, если есть. Карточка `--card` + тень.
- Тулбар: «← К поиску», «+ Новый альбом» (градиент), «+ Курс».

## L3 — Альбом (`_ppRenderAlbum`)

- **Тулбар:** «‹ Пациент», заголовок «Альбом · <дата>» (без переноса — короткий формат даты), справа кнопка **⋯** открывающая меню с пунктом «Удалить альбом» (разрушающее действие убрано из основного ряда; стиль — `--danger`).
- **Карточка-сравнение (вверху):** грид 2 колонки, левое фото с меткой «ДО» (тёмная плашка), правое — с меткой «ПОСЛЕ» (плашка `--grad-a`); подпись-подвал «Результат» цветом `--a`. **Показывается только если есть хотя бы одно фото `before` И одно `after`.** Авто-подбор: первое (старейшее) фото `before` + последнее (новейшее) фото `after`. Клик по половине — открывает её в лайтбоксе.
- **Карточки стадий ДО / В процессе / ПОСЛЕ:** мягкая карточка `--card` со скруглением; заголовок стадии + чип-счётчик + «+ фото» (`--a`). Сетка фото — `grid-template-columns:repeat(3,1fr)` на мобильном (тянется по ширине экрана), `repeat(auto-fill,120px)` на десктопе; скругление миниатюр, gap 3–8px. «После» получает верхнюю градиентную полосу и бирюзовый чип.
- **Пустая стадия** → дашед-дропзона: рамка `1.5px dashed --bd`, иконка «＋», текст «<Стадия> — добавить фото», по клику — тот же `input[type=file]`. Заменяет серый «Нет фото».
- **Прогресс-загрузки, лайтбокс, заметки, комментарии** — функционал без изменений; визуально приводятся к новому языку (скругления/цвета через переменные). Прогресс-бар (`.pp-upload-*`) уже сделан — сохраняется.

## Данные и интеграция (backend)

Обе правки дешёвые: соответствующие эндпоинты **уже** в цикле выбирают все фото визита со `stage` (для подбора превью) — флаги вычисляются там же, без новых запросов.

1. **Бейдж «До·После» (L1).** В `GET /visits/recent` (и для единообразия в `GET /clients/:clientId/cases`) в существующем цикле по `photos` выставлять `v.has_before = photos.some(p=>p.stage==='before')` и `v.has_after = photos.some(p=>p.stage==='after')`. Фронт рисует бейдж при `has_before && has_after`.
2. **Шапка пациента (L2).** Имя/телефон для шапки: добавить в ответ `GET /clients/:clientId/cases` поля `client_name`/`client_phone` (через `JOIN clients`) — надёжно при перезагрузке. Альтернатива без backend: класть имя в `_ppState.clientName` при переходе из поиска. **Решение:** backend-JOIN (устойчивее).

Эндпоинт `GET /visits/:id` уже отдаёт `photos[]` со `stage`, `sort_order`, `uploaded_at` — данных для карточки-сравнения достаточно (подбор «первое before / последнее after» — на фронте).

## Тёмная тема

Проверить оба режима (переключатель темы в топбаре). Тинты «после» (`#c8efe2`, `#e3f8f0`) и тени с зелёным glow заданы под светлую тему — для тёмной использовать переменные/`--as` либо отдельные значения в блоке `[data-theme="dark"]`, чтобы не было блёклых пятен.

## Тестирование

Ручная визуальная проверка через MCP Playwright на dev-сервере (`localhost:3001`, вход owner):
- 390×844 (мобайл) и ~1280 (десктоп) — все три уровня.
- Светлая и тёмная темы.
- Альбом с обеими стадиями (есть карточка-сравнение и бейдж в ленте) и альбом только с «До» (карточки-сравнения нет, бейджа нет).
- Пустая стадия показывает дропзону; клик открывает выбор файла; загрузка с прогресс-баром по-прежнему работает.
- Меню ⋯ → «Удалить альбом» удаляет и возвращает на L2.
- Бэкенд: `node` — существующие тесты портфолио (`portfolio.test.js`) не затронуты; новые флаги `has_before/has_after` проверяются вручную через ответ API.
