# Услуги и назначения специалистов — 17.11.2026

Реализация запроса владельца: базовые цена/длительность услуги и отдельные значения для назначенного специалиста. План: `../plans/2026-11-17-service-staff-settings.md`. Этот документ дополняет спецификацию внутреннего каталога от 08.11.2026; обычный импорт по-прежнему только добавляет отсутствующие услуги.

## Поведение

- Карточка услуги содержит назначения существующих специалистов своего салона. Для каждого независимо выбираются базовая или индивидуальная цена и длительность. Ноль рублей — реальное значение; `null` — наследование. Минимальная длительность 1 минута, максимальная 1440.
- Цена поддерживает прежний диапазон. Индивидуальная `priceMin` без `priceMax` означает фиксированную цену; `priceMax` без минимума запрещена. Явное значение, равное базовому, остаётся явным при последующих изменениях базы.
- Редактировать могут owner/admin. Сервер определяет салон по сессии. Неактивного сотрудника назначить нельзя; его старое назначение видно для исправления, но не используется для новых записей после перевода услуги на новую модель.
- Пустой список назначений допустим: услуга остаётся в каталоге, но не предлагается для новой записи. Удаление назначения не удаляет специалиста и не меняет старые визиты.
- Несопоставленные старые назначения требуют явного подтверждения замены; обычное сохранение не может потерять их незаметно.
- Карточка передаёт `version`; устаревшее сохранение получает 409. Старые клиенты без поля `assignments` сохраняют назначения неизменными. Версия увеличивается и при таком редактировании.
- Историческая длительность карточки визита берётся из снимка услуги/визита, а не из сегодняшнего прайса. Для нескольких услуг без сохранённой разбивки длительность отдельной строки не выдумывается.

## Данные и API

В `backend/migrations.js` добавлен `SERVICE_STAFF_ASSIGNMENTS_DDL`, выполняемый после создания `staff_members`:

- `service_catalog.assignments_initialized` и `version`;
- `service_staff_assignments`: салон, внутренние ID услуги и сотрудника, nullable индивидуальные цены/длительность, источник и время изменения;
- составные tenant FK, уникальность пары и индекс по сотруднику;
- `service_catalog_sync_runs`: неизменяемый снимок до/после сверки, tenant/company, статус и время применения.

Автоматического backfill при старте нет. Существующий JSON `staff` сохраняется для совместимости; после редактирования назначения он обновляется атомарно с отдельной таблицей. `assignments_initialized=true` отличает сознательно пустой список от ещё не переведённой услуги. Основные поля услуги и назначений читаются одним PostgreSQL snapshot через коррелированный подзапрос, чтобы не смешать версии параллельного сохранения.

`GET /api/service-catalog` дополнительно возвращает `staffMembers`, у услуг — `assignments`, `assignmentsUnresolved`, `version`. Назначение: `{staffMemberId,priceMin,priceMax,duration}`. Сохранение через прежние POST/PUT `/services` принимает тот же массив и версию; для подтверждённой замены несопоставленных связей — `replaceUnresolvedAssignments:true`.

`POST /api/service-catalog/reconcile/preview` читает Yclients, формирует и сохраняет снимок, возвращает `runId`, список целей до/после, исключения и агрегаты. `POST /reconcile/:runId/apply` применяет только сохранённый снимок своего салона. Клиент не передаёт произвольные целевые изменения в apply.

## Журнал, AI и бронирование

`service-assignment-values.js` задаёт наследование. `service-catalog-policy.js` адаптирует переведённые локальные услуги для внешних ID потребителей, без собственного кэша.

- Журнал берёт локальную цену/длительность; индивидуальные значения участвуют в расчёте слотов, количества и новых строк записи. Ручные цены черновика сохраняются.
- Добавление услуги и смена специалиста проверяются на сервере. Существующие строки визита не становятся недоступными для просмотра/обычной правки из-за последующей смены каталога.
- AI-каталог использует пересечение локальных назначений и прежнего внешнего каталога, сохраняя allow/deny, скрытые пары и прочие ограничения. Локальное назначение не включает автоматически услугу, скрытую исходными правилами агента, в том числе прежним фильтром нулевых внешних цен.
- Одиночные, параллельные и последовательные слоты учитывают длительность каждого выбранного специалиста. Перед внешним созданием пары подтверждаются свежим запросом Yclients. Смешанный набор переведённых и старых услуг считает каждую длительность отдельно.
- У новой добавленной услуги применяется локальная цена/длительность; согласованные суммы и длительность сохранённой части визита не перезаписываются настройками каталога. При удалении строки её время вычитается только при наличии сохранённой длительности этой строки; без исторической разбивки сохраняется прежний интервал, а не подставляются сегодняшние настройки. При полной замене набора длительность рассчитывается заново.
- Не переведённые услуги сохраняют прежний режим. Обратной записи настроек каталога в Yclients нет; новая локальная связь не доказывает наличие внешнего назначения.

## Перенос и восстановление

- Сетевые чтения выполняются до короткой транзакции. Сохранение карточек, импорт и apply используют общий tenant advisory lock.
- Preview содержит полный before/target, fingerprint локальных версий/назначений/сотрудников/company и время. Apply старше 30 минут или при изменении локального состояния отклоняется: нужна новая сверка.
- Неактивные назначения явно перечислены как исключаемые; неизвестные связи не угадываются. Некорректная длительность оставляет целую услугу без изменений и видна в исключениях.
- Применение атомарно. Повтор одного run ID возвращает alreadyApplied и ничего не изменяет. История визитов, финансов и бонусов не затрагивается.
- Откат кода сохраняет новые таблицы и JSON. Для восстановления настроек использовать `snapshot.targets[].before` соответствующего run, только после проверки, что версия каждой услуги не изменилась после apply. Если есть более поздние правки — отдельная сверка, а не слепое восстановление. Сохранять резервную копию перед выкладкой/переносом. Удалять новые таблицы не требуется.

## Единый справочник: экономика и журнал

Дополнение по запросу владельца: настройки услуг — единственный редактируемый справочник. Экономика читает текущие названия, категории и базовые длительности из локального каталога, а её вкладка «Рентабельность услуг» остаётся отчётом по состоявшимся визитам за период. Исторические цены/названия строк визитов и существующие внешние ключи расчётов сохраняются; они не являются вторым редактируемым справочником. Локальные ID не подставляются вместо внешних ключей оплаты труда/техкарт.

После изменения каталога сбрасывается серверный кэш отчётов данного салона; повторный вход в экономику обновляет справочники и отчёт. Новые услуги при создании и редактировании записи выбираются только из каталога настроек и только при назначении выбранному специалисту. Сервер проверяет то же ограничение. Сохранённые строки существующего визита остаются доступны для просмотра даже после снятия назначения.
