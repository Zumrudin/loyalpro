# Бумажные папки: 2000 повторно используемых номеров

Статус: реализация по согласованным в переписке правилам, 24.11.2026. Выкладка и изменения production не выполнялись.

## Правила

- У каждого салона свой пул номеров 1–2000. Номер обозначает папку в шкафу; юридический номер договора остаётся отдельным и не меняется.
- При записи первичного пациента или пациента с отметкой «Архив» автоматически резервируется минимальный свободный номер. Несколько записей пациента используют одну папку. Первичность определяется отсутствием известной истории посещений; старые действующие бумажные пакеты регистрируются отдельно.
- Первичные локальные записи журнала резервируют номер ещё до отправки в YClients. Пока нет карточки пациента, резерв связан с локальной записью. После однозначного сопоставления карточки номер сохраняется. Неоднозначные совпадения не объединяются автоматически.
- У архивного пациента номер появляется при записи, но «Архив» остаётся до подтверждённых attendance=1 И paid_full=1. Оптимистичные локальные оплаты/отметки прихода не снимают архив. История прошлых оплаченных визитов не является основанием снять архив.
- «Пакет создан» — отдельная физическая отметка. Выполнение и оплата визита не подтверждают наличие бумаг, но закрепляют номер и защищают его от автоматического освобождения.
- Перенос в архив подтверждается сотрудником после извлечения бумаги. Номер освобождается; прежние закрепления остаются в журнале событий. Пока есть ожидаемый визит на сегодня/будущее, архивирование отклоняется.
- Ручное снятие «Архив» отключено: действует согласованное автоматическое правило. Для повторного переноса подготовленного пакета ещё архивного пациента предусмотрено отдельное действие с подтверждением.
- При отмене/неявке/удалении последней записи автоматически освобождается только предварительный номер без созданного/закреплённого пакета. Наличие других действующих записей сохраняет резерв.
- При заполнении шкафа запись сохраняется без номера, в списке появляется задача. Номер 2001 не выдаётся. Периодическая сверка раз в минуту повторяет обработку и выдаёт освободившиеся номера.
- «Рабочий день»: дата по умолчанию завтра в Europe/Moscow, выбор даты, одна строка на пациента, сортировка по номеру, вместимость/свободные места, задача оформить новый договор, физическая отметка пакета и время обновления. Учитываются локальные переносы и отмены журнала.
- Поля местонахождения, автоматического уничтожения документов и перенумерации подписанных договоров нет.

## Хранение и безопасность

`PAPER_FOLDERS_DDL` в `backend/migrations.js` добавляет `paper_folders` и `paper_folder_events`. Уникальность `(salon_id,number)`, диапазон CHECK 1–2000, одна активная строка на клиента/локальный резерв. Все операции выдачи/возврата сериализованы advisory transaction lock салона; изменение и событие фиксируются одной транзакцией. Данные карточки клиента связаны составным FK `(salon_id,client_id)`.

Журнал содержит идентификаторы, номер, действие, время и сотрудника. Контактные данные и тексты документов в него не копируются. Доступ к изменению папок и списку дня — owner/admin; salon_id и сотрудник берутся из проверенной сессии. Ошибки фонового учёта не отменяют созданную запись или проведённую оплату и не выводят данные пациента в лог.

## API

- `GET /api/clients/:id`: дополнительное `client.paper_folder`.
- `PATCH /api/clients/:id/paper-folder`: ровно одно из `{archived:true}`, `{prepared:boolean}`, `{number:1..2000}`. Ручной номер нужен только для регистрации существующего пакета без номера; чужой занятый номер недоступен.
- `GET /api/paper-folders/day?date=YYYY-MM-DD`: список и сводка шкафа; чтение без мутаций.
- `PATCH /api/paper-folders/outbox/:id`: `{prepared:boolean}` для нового локального пациента до появления его карточки.

Событийные вызовы: зеркало/вебхуки YClients, локальные сохранения и удаления журнала, подтверждённые оплаты журнала, мобильные изменения статуса и создание записи агентом. В последнем случае неизвестная ещё локально карточка обрабатывается после её появления из вебхука/синхронизации. Периодическая сверка восстанавливает пропущенную обработку. Новых внешних сообщений, изменений записей и операций с бонусами сервис папок не делает.

## Внедрение и откат

1. Подготовить шкаф с номерами 1–2000 и зарегистрировать существующие пакеты через карточки клиентов. Номер договора из YClients автоматически в номер папки не импортировать: значения имеют разный смысл.
2. Перед выкладкой получить отдельное разрешение на production migration/deploy и штатную резервную копию.
3. Добавочная миграция запускается штатным `runMigrations` до запуска фонового сверщика. Нет backfill, удаления или массового изменения клиентов/договоров. Уникальный индекс клиентов уже используется другими миграциями; на старом окружении его первое создание может кратковременно блокировать запись. Применять в согласованном окне с ограниченными lock/statement timeout, при конфликте остановить выкладку.
4. Старый код совместим с добавочными таблицами. Новый GET карточки допускает отсутствие таблицы до миграции; новые операции требуют установленной схемы. При откате вернуть прежнее приложение, таблицы и аудит сохранить. Пока старая версия активна, новые выдачи/возвраты номеров приостановить и сверить перед повторным включением.
5. Не считать исторический пакет архивным автоматически по возрасту: физическое освобождение подтверждает сотрудник. Массовое архивирование и перенос существующих данных не входят в эту миграцию.
