# Расписание работы ИИ-агента «Мила»

**Дата:** 2026-07-30
**Ветка:** feat/chat-v2

## Задача

Дать салону возможность включать агента по расписанию: например, отвечать **всем**
клиентам с 22:00 до 09:30, а в остальное время — только тестовым номерам. Цель
владельца: пока Мила дорабатывается, обкатывать её на ночном потоке, ловить баги,
не рискуя дневным трафиком.

## Принцип

**Расписание только сужает допуск, никогда не расширяет.**

Внутри окна действует режим, выбранный в админке (`all` или `whitelist`).
Вне окна режим принудительно становится `whitelist` — отвечаем только номерам
белого списка. Так тестовые номера работают круглосуточно, а «все остальные»
получают Милу лишь в отведённые часы.

При `mode='whitelist'` расписание не меняет ничего: режим и так самый узкий.

## Модель данных

Три колонки в существующую таблицу `agent_settings` (миграция
`ADD COLUMN IF NOT EXISTS`, как принято в проекте):

| Колонка            | Тип         | Default   | Смысл                            |
|--------------------|-------------|-----------|----------------------------------|
| `schedule_enabled` | BOOLEAN     | `FALSE`   | расписание учитывается           |
| `schedule_start`   | VARCHAR(5)  | `'22:00'` | начало окна, московское время    |
| `schedule_end`     | VARCHAR(5)  | `'09:30'` | конец окна, московское время     |

Формат `'HH:MM'` выбран вместо `TIME`, чтобы не зависеть от того, как драйвер `pg`
конвертирует `TIME` в JS-значение, и чтобы значение читалось глазами в БД.
Валидация формата — на входе API.

Новых таблиц нет. Дни недели и несколько окон в сутки — вне объёма (YAGNI).

## Логика допуска

### `decideGate` (backend/services/agent-gate.js) — чистая функция

Расширяется параметрами `{ scheduleEnabled, scheduleStart, scheduleEnd, nowMinutes }`.
Новый порядок решений:

1. `!enabled` → `{ allow: false, reason: 'disabled' }`
2. номер в чёрном списке → `{ allow: false, reason: 'blacklisted' }`
   (чёрный список приоритетнее расписания всегда)
3. если `scheduleEnabled` **и** окно валидно **и** `nowMinutes` вне окна →
   эффективный режим `whitelist`; иначе эффективный режим = `mode`
4. эффективный `whitelist` и номера нет в белом списке → `allow: false`,
   `reason: 'outside-schedule'` если отсекло расписание, `'not-whitelisted'`
   если отсёк выбранный режим (разные reason — чтобы в логах диспетчера было
   видно, что именно сработало)
5. иначе → `{ allow: true, reason: 'ok' }`

### Хелперы (там же)

- `parseHhMm('09:30') → 570` — минуты от полуночи; `null` при любом мусоре
  (пустая строка, `'25:00'`, `'9:3'`, `undefined`).
- `isWithinWindow(nowMinutes, startMin, endMin) → boolean`:
  - `start < end` — обычное окно: `now >= start && now < end`
  - `start > end` — окно через полночь: `now >= start || now < end`
  - `start === end` — вырожденное; считаем окном **нулевой длины** (всегда `false`),
    чтобы «22:00–22:00» не означало молча «круглые сутки».

Границы: начало включительно, конец исключительно. В 09:30:00 ровно агент уже
вне окна.

**Fail-open к текущему поведению:** если `parseHhMm` вернул `null` для любой из
границ, расписание игнорируется целиком (работает как `schedule_enabled=false`).
Битая настройка не должна приводить к круглосуточному молчанию — это заметно
хуже, чем к круглосуточной работе, потому что выглядит как «бот сломался».

### Часовой пояс

`decideGate` получает `nowMinutes` числом и остаётся чистой. Считает его тонкая
обёртка `nowMskMinutes` в том же `agent-gate.js` (не в `agent-settings.js`:
оттуда её не покрыть Jest'ом, не подтянув `db.js` с живым пулом к Beget):

```js
function nowMskMinutes(date = new Date()) {
  const s = date.toLocaleTimeString('ru-RU', {
    timeZone: 'Europe/Moscow', hour12: false,
    hour: '2-digit', minute: '2-digit',
  });                       // '22:07'
  const [h, m] = s.split(':').map(Number);
  return h * 60 + m;
}
```

Явный `timeZone`, а не локальный TZ процесса: сервер сейчас на `Europe/Moscow`,
но привязка к этому — скрытая зависимость.

### `isAllowed` (backend/services/agent-settings.js)

`getSettings` возвращает новые поля; `isAllowed` прокидывает их и `nowMskMinutes()`
в `decideGate`. Точка вызова в `services/agent/dispatcher.js` не меняется — гейт
уже вызывается на каждое входящее и уже fail-closed при исключении.

## Границы диалога

Отсечка жёсткая по часам, без грейс-периода. Диалог, начатый в 09:25 и
продолженный клиентом в 09:35, дальше бот не ведёт: сообщение остаётся в чате
админки, администратор подхватывает вручную. Состояние диалога в гейте не
учитывается — никаких запросов истории, никакого нового состояния.

## API

`GET /api/agent/settings` → `{ enabled, mode, scheduleEnabled, scheduleStart, scheduleEnd }`

`PUT /api/agent/settings` принимает те же поля. Валидация: `scheduleStart` и
`scheduleEnd` должны парситься как `HH:MM` → иначе `400 { error: 'Некорректное время расписания' }`.
Поля расписания, **отсутствующие** в теле запроса, сохраняют текущее значение из
БД. Иначе старый закэшированный фронт, шлющий только `{enabled, mode}`, молча
сбросил бы окно.

Роли не меняются: `owner`/`admin`.

## Фронтенд

`frontend/index.html`, модалка `agent-settings-modal`, под радиокнопками режима:

- чекбокс `agent-schedule-enabled` — «Работать по расписанию»
- два `<input type="time">`: `agent-schedule-start`, `agent-schedule-end`
- подпись: «Вне окна отвечает только номерам из белого списка»
- поля времени гасятся (`opacity`/`pointer-events`), когда чекбокс снят —
  тем же приёмом, что уже используется для секции белого списка

`frontend/js/pages/agent-settings.js`:

- `openAgentSettings` заполняет новые контролы из ответа API
- `saveAgentSettings` отправляет новые поля
- `_agentToggleAllowSection` правится: сейчас белый список гаснет при режиме
  «Всем», но с включённым расписанием он снова значим. Новое условие гашения:
  режим `all` **и** расписание выключено.

## Тесты

`backend/agent-gate.test.js` (юниты чистой функции, без БД):

- `parseHhMm`: валидные значения, `'25:00'`, `'9:3'`, `''`, `undefined` → `null`
- обычное окно `09:00–18:00`: внутри / до / после
- окно через полночь `22:00–09:30`: 23:00 внутри, 02:00 внутри, 12:00 вне
- границы: ровно `22:00` — внутри; ровно `09:30` — вне
- вне окна: номер из белого списка проходит; чужой → `outside-schedule`
- чёрный список бьёт расписание (внутри окна номер из чёрного всё равно отклонён)
- `scheduleEnabled=false` → поведение идентично текущему
- битый формат времени → расписание игнорируется (не молчание)
- `mode='whitelist'` + расписание → внутри окна по-прежнему только белый список

Существующие кейсы `agent-gate.test.js` и `agent-dispatcher.test.js` должны
остаться зелёными без правок: новые параметры `decideGate` опциональны.
