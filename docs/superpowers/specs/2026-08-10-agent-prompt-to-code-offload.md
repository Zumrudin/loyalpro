# Спека: перевод промпт-правил Милы в детерминированный код (стабильность + стоимость)

Дата: 2026-08-10. Статус: утверждена к реализации.

## 1. Цель и фон

Системный промпт Милы — ~39k токенов и >100 правил; действует мораторий (c9301fd):
новые поведенческие дефекты закрываются только детерминированно. Эта спека — обратный
перенос: какие из УЖЕ существующих промпт-правил можно продублировать или заменить кодом.

Два эффекта:
- **Стоимость.** Главная экономия — не укорачивание префикса (он кэшируется, ~10% цены),
  а снятие целых LLM-проходов: каждый tool-round-trip — это ещё один полный проход по
  всему промпту. Две ветки (оценка визита, предвызов КБ на «+») убирают по 1–2 прохода
  на типовом сценарии.
- **Стабильность.** Правила-арифметика (диапазоны цен направлений) и правила-запреты
  (цена единицы Ботулакса, запись на неназванный препарат, повтор должности) получают
  детерминированный рубеж — промпт-правила в этом проекте многократно проигрывали
  живым прогонам (greeting 1/3, care-skip 6/6, дубли вызовов 9/ход).

## 2. НЕ входит в объём (проверено по коду 10.08)

- **Валидация `record_id` в cancel/reschedule** — УЖЕ реализована: fail-closed гейт
  `expectedYcClientId` в обоих инструментах + проверка принадлежности в
  `booking-modify` (ответ `foreign`).
- **Слова-табу и внутренние id** — уже в reply-guard (`taboo_word`/`id_leak`, HARD).
- **Кап эмодзи** — уже в reply-guard (`emoji_excess`, лог).
- **Сокращение префикса промпта** (ужать правила, продублированные кодом) — отложено:
  промпт защищён тестами (урок dd6d2fd), выгода мала (кэш), риск регрессов высок.
  Делать отдельной работой после накопления телеметрии.
- **Guard обобщённых услуг для ботулинотерапии (зон)** — намеренно НЕ охраняется:
  зона в тексте пациента склоняется («лба» при услуге «Лоб+Межбровье»), стем-сверка
  дала бы ложные срабатывания на самом частом легальном пути, а каждое ложное — лишний
  проход провайдера. Охраняются только «препаратные» направления по латинским брендам.
- **Guard обобщённых услуг в book_chain** — не в объёме: услуги цепочки выбраны через
  get_sequential_slots, инцидентный класс (2026-07-31) — прямой create_booking.
- **Хардкод имён специалистов PERI в промпте** — мультисалонный долг, отдельная работа.

## 3. W1 — Оценка визита («5») без LLM

Правило промпта «ОЦЕНКА ВИЗИТА» остаётся (смешанные ответы «5, и запишите ещё…»,
выключенный флаг), но чистый случай обрабатывается детерминированной веткой в
оркестраторе — тем же приёмом, что `closing.js` (проверка ДО провайдера).

**Условие срабатывания (оба обязательны):**
1. Последний блок транскрипта — user, и его текст после срезки меток времени,
   эмодзи и пунктуации — РОВНО одна цифра 2–5 («5», «5!», «5)» проходят;
   «5 отлично», «5 из 5» — нет, их ведёт LLM по правилу промпта).
2. Последнее исходящее диалога имеет `authored_by='system'` (новый хелпер
   `history.lastOutgoingAuthor`): пациент отвечает на автоуведомление, а не на
   вопрос Милы — её вопрос сделал бы последним исходящим `'agent'`.

**Поведение:** ватермарк двигается как в штатном ходе. Оценка 4–5 → шаблонная
благодарность (с именем через `sanitizeName`, без вопросов и продаж), провайдер не
вызывается. Оценка 2–3 → извинение + эскалация (прямой вызов хендлера
`escalate_to_operator` с reason «низкая оценка визита (N)»); текст извинения содержит
слово «администратор» (диспетчер тогда не дошлёт вторую фразу перевода) и учитывает
окно администратора (`adminOffHours`).

**Fail-open:** сбой `lastOutgoingAuthor` или отсутствие метода в инжекторе → ветка
не срабатывает, ход идёт через LLM как раньше. Флаг `AGENT_VISIT_RATING_REPLY`
(default ВКЛЮЧЕНО, гасится `=false`).

**Остаточный риск (принят):** голая цифра 2–5 в ответ на вопрос Милы, между которыми
вклинилось автоуведомление, прочитается как оценка. Сценарий сконструированный
(ответ цифрой без слов на вопрос, при этом последнее исходящее — system), цена —
вежливая благодарность вместо ответа, т.е. не хуже инцидентного поведения 2026-08-10.

## 4. W2 — Предвызов КБ на короткое «+» (акция)

Правило «СПЕЦПРЕДЛОЖЕНИЕ МЕСЯЦА» требует от модели вызвать `search_knowledge_base` —
это два прохода провайдера. Оркестратор делает вызов САМ до первого прохода.

**Условие:** последний user-блок — голое «+» (1–3 плюса) или «плюс» И
`lastOutgoingAuthor === 'system'` (согласие именно на отбивку клиники, а не на
предложенный Милой слот — там последнее исходящее `'agent'`). Триггер намеренно
УЖЕ промпт-правила («да», «расскажите» не триггерят): цена ложного срабатывания —
нерелевантный блок в промпте, поэтому берём только однозначные формы.

**Поведение:** один вызов хендлера `search_knowledge_base` с запросом
«спецпредложение месяца, акция» (та же формулировка, что в правиле промпта).
`found:true` → статья уезжает волатильным блоком «СТАТЬЯ О СПЕЦПРЕДЛОЖЕНИИ МЕСЯЦА»
в САМЫЙ хвост промпта (после всех существующих хвостовых блоков — инвариант
«промпт без блока — префикс промпта с блоком» сохраняется), вызов пишется в
`evBuffer` (память/форензика) и в `kbSourceText` (address-guard считает статью
легальным источником этого хода). `found:false` → блока нет, модель идёт своим
путём (вызовет сама, получит found:false, уведёт на администратора по правилу).
Предвызов делается один раз на ход (переживает перегенерации).

**Правка правила промпта** (уточнение существующего, по моратории допустимо):
в «ЧТО ДЕЛАТЬ» добавляется: если блок статьи уже есть в конце промпта — отвечать
по нему и `search_knowledge_base` не вызывать.

Флаг `AGENT_PROMO_PREFETCH` (default ВКЛЮЧЕНО).

## 5. W3 — Диапазоны цен направлений в каталоге + маскировка цены Ботулакса

**5а. Предрассчитанные диапазоны.** Сегодня модель сама отбирает услуги по
`category_path`, исключает «инд.» и Ботулакс и считает min/max — чистая арифметика,
хрупкая в LLM. `catalog-block.js` дополняется детерминированным блоком
«ДИАПАЗОНЫ ЦЕН…» сразу после строк каталога (внутри того же кэшируемого
`catalogBlock`): по каждому УЗЛУ `category_path` (направление И подкатегория) —
диапазон женских услуг и отдельно мужских («Муж.», через `isMaleService`).
Исключаются: услуги с ценой «инд.» (заглушки ≤100 ₽ и «настоящие инд.»),
услуги без цены, «Ботулинотерапия Ботулакс 1 ед» (см. 5б). Формат строки:

```
- «Биоревитализация»: от 12000 до 21000 ₽
- «Инъекционная косметология»: от 3000 до 25000 ₽ (мужской прайс «Муж.»: от 4900 до 29900 ₽)
- «Комплексы»: только мужской прайс «Муж.» — 24700 ₽
```

lo===hi → одно число «N ₽». Сортировка строк — по имени узла простым сравнением
строк (детерминизм префикс-кэша; localeCompare не используется — зависит от ICU).

**5б. Цена единицы Ботулакса.** Инцидентный запрет «цену "Ботулакс 1 ед" пациенту
не называй» держится только на промпте, а 370 ₽ стоит в каталоге открытым текстом.
Тот же приём, что с заглушкой 1 ₽: строка этой услуги рендерится с ценой «инд.» и
колонкой мастеров БЕЗ цен (только id) — модель физически не видит числа.
Распознавание — существующий `matchesGenericTitle(title, 'Ботулинотерапия Ботулакс 1 ед')`.
Побочно услуга автоматически выпадает из диапазонов 5а («инд.» исключается).

**5в. Правка правила «Цена НАПРАВЛЕНИЯ» (catalogMode-ветка):** диапазон брать из
блока «ДИАПАЗОНЫ ЦЕН», самой не пересчитывать; прежний расчёт через category_path
остаётся фолбэком «если направления в блоке нет». Начало формулировки
(«Цена НАПРАВЛЕНИЯ (пациент спрашивает стоимость целого направления…») сохраняется —
на него завязаны тесты. Legacy-ветка (без каталога в промпте) не меняется.

## 6. W4 — Guard обобщённых услуг в create_booking

Инцидент 2026-07-31: запись на «Revi Silk 1 ml» вместо обобщённой
«Биоревитализации», когда пациент препарат не называл. Закрыто только промптом.

**Правило (чистый модуль `generic-booking-guard.js`):** create_booking на услугу,
которая (1) лежит в одном из направлений «Биоревитализация» / «Увеличение губ» /
«Контурная пластика» (узел `category_path`, сравнение без регистра и с ё→е),
(2) НЕ является самой обобщённой услугой (`matchesGenericTitle`), (3) содержит в
названии ЛАТИНСКИЙ брендовый токен (≥3 латинских букв подряд: Revi, Stylage,
Profhilo…), (4) ни один из этих токенов не встречается в тексте сообщений пациента
(`ctx.patientText`, прокидывает оркестратор), и (5) обобщённая услуга направления
ЕСТЬ в каталоге (иначе правило невыполнимо — fail-open, как `warnMissingGenericServices`),
— НЕ исполняется: возвращается `generic_service_hint:true` с указанием
`service_yc_id` обобщённой услуги и инструкцией.

**Обход:** новый параметр схемы `patient_named_service:boolean` — модель ставит его,
только если пациент назвал препарат своими словами (кириллицей «стилаж» и т.п.).
Guard при нём пропускает. Названия только из русских слов (без латиницы) не
охраняются вовсе — там судить не по чему.

## 7. W5 — «Должность один раз за диалог» детерминированно

Чистый модуль `title-dedup.js`: если пара «должность + Имя» уже звучала в ПРОШЛЫХ
репликах Милы (assistant-блоки транскрипта минус строки с `OPERATOR_MARK`, минус
метки времени), в новой реплике должность перед этим именем срезается: «у
косметолога-эстетиста Юлии» → «у Юлии» (имя несёт падеж — конструкция остаётся
грамматичной, поэтому чистая текстовая замена безопасна). Должности — паттерны со
склонением: «главн… врач…», «врач…-косметолог…», «косметолог…-эстетист…». Имя
сверяется по стему (как `mentionsPerson` в reply-guard). Первое упоминание в
текущей реплике не трогается. Каждый срез логируется. Место в оркестраторе — после
`stripStamp` (реплики финальны), до address-guard.

## 8. W6 — Телеметрия повтора «консультация в подарок»

Правило «один раз за диалог» — только измерение (как `offer_bypass`): новый
лог-only тип `gift_repeat` в reply-guard — фраза «в подарок» в реплике при уже
существующей в прошлых репликах Милы. Переписывания нет: резать текст с
упоминанием подарка рискованно, а масштаб проблемы неизвестен.

## 9. Флаги и откат

- `AGENT_VISIT_RATING_REPLY=false` — гасит ветку оценки (ход уходит в LLM).
- `AGENT_PROMO_PREFETCH=false` — гасит предвызов КБ.
- W3/W5/W6 — без флагов: чистые рендер/построкинг, откат — revert коммита.
- W4 — без флага: у модели есть штатный обход `patient_named_service`.

## 10. Порядок детерминированных проверок в оркестраторе (итоговый)

`loadTranscript` → closing (молчание) → **W1 оценка визита** → evBuffer →
**W2 предвызов КБ** → prompt → LLM-цикл → false-claim довызов → reply-guard
(+ **W6 gift_repeat**) → stripStamp → **W5 title-dedup** → address-guard →
ensureGreeting → ensureIntroduction.
