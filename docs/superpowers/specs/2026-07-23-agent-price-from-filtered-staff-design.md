# Дизайн: цена и длительность услуги агента — только по отфильтрованным мастерам

Дата: 2026-07-23
Модуль: `backend/services/agent/tools/list-services.js`, `backend/services/yclients.js`, `backend/services/agent/system-prompt.js`

## Проблема

Мила в одном диалоге называла «Лазерная эпиляция, ноги полностью» то за 21 000 ₽, то за
5 000 ₽, а разницу объяснила выдуманным «мужская vs женская эпиляция» (галлюцинация — в
данных такого признака нет).

Корень — в форме данных, а не в загрузке. В `list-services.js:79-80` услуга отдаёт в модель
**сырой диапазон `price_min`/`price_max` из общего каталога YClients** (`/services/{cid}`).
Этот диапазон считается по ВСЕМ мастерам, у кого в YClients есть доступ к услуге — включая
тех, кого «страница услуги агента» исключила deny-парой (мастер имеет доступ в YClients, но
по факту услугу не делает; например, врач делает её только на своё усмотрение, самозапись
запрещена). «Теневой» мастер тащит в диапазон свою цену (21 000), и модель называет то верх,
то низ диапазона.

## Целевой порядок (источник истины)

Для каждой услуги:

1. **Кто делает** — «страница агента»: реальная привязка `staffIdsByService` (per-staff запросы
   YClients) **минус** `denyPairs` через `filterServiceStaff`. Уже реализовано.
2. **Цена и длительность** — из живого YClients, но **считаются ТОЛЬКО по отфильтрованному
   списку мастеров** из шага 1. Сырой `price_min/price_max` уровня услуги в модель больше не
   уходит.
3. Если после фильтра **не осталось мастеров** — услуга не показывается вовсе (сейчас показалась
   бы с пустым `staff[]`, но с «теневой» ценой из каталога).

## Изменения

### `list-services.js`

- Убрать `price_min: s.price_min, price_max: s.price_max` на уровне услуги (стр. 79-80).
- Считать `price_min`/`price_max` услуги как **min/max по ценам отфильтрованных мастеров**
  (результат `staffOf(s)`). Каждый мастер уже несёт свою цену с фолбэком на service-level, если
  YClients не отдал per-staff цену (стр. 65-66 — оставляем: мастер уже прошёл фильтр «реально
  делает», service-level для него — лучшая доступная оценка).
- Добавить в объект услуги `duration_min` — длительность услуги (service-level) из
  `ycGetServiceMeta(salon)` → `durationByService` (секунды → минуты). Per-staff длительности в
  YClients booking API нет (management-эндпоинт даёт только service-level), поэтому длительность
  одна для всех мастеров услуги — это ограничение YClients, не наше.
- Дополнить фильтр видимости: услуга показывается только если
  `decideOfferVisible(...) && staffOf(s).length > 0`.
- В `run()` дополнительно вызвать `ycGetServiceMeta(salon)` (кэш 10 мин) для длительностей.

Итоговый объект услуги для модели:
```js
{ yc_id, title, duration_min, price_min, price_max, staff: [{yc_id, name, price_min, price_max}] }
```
где `price_min`/`price_max` — агрегаты по `staff[]`, а не по сырому каталогу.

### `system-prompt.js` (строка 109)

Дополнить правило о цене одной фразой: **не выдумывать причину разницы цен между мастерами**
(«мужская/женская», «мощнее аппарат» и т.п.) — называть только факт цены. Причина разброса —
это разные мастера, а не выдуманные свойства процедуры.

## Крайние случаи

- **У всех отфильтрованных мастеров нет per-staff цены** → все падают на service-level фолбэк →
  диапазон = service-level (как раньше). Редкий случай (YClients обычно отдаёт per-staff цену);
  «теневого» мастера в списке уже нет, т.к. он отфильтрован.
- **YClients недоступен** → существующий фолбэк на заголовки из `services_config` с
  `price_min/max = null`, `duration_min = null`, `staff = []` — не трогаем.
- **Длительность отсутствует в мете** → `duration_min: null`, модель просто не называет время.

## Тесты

- Юнит-тест для `staffOf`/агрегации цены: услуга с «теневым» мастером (deny-пара, цена 21 000) и
  двумя рабочими (5 000) → в ответе `price_min=price_max=5000`, `staff` без теневого.
- Услуга, где после фильтра не осталось мастеров → не попадает в `services`.
- `duration_min` прокидывается из меты.
- После правки промпта прогнать `jest agent-system-prompt` (промпт защищён тестами — см.
  память feedback_agent_prompt_test_guarded).

## Вне scope

- Per-staff длительность (YClients её не даёт).
- UI «страницы услуги агента» — механизм deny-пар уже есть, менять не нужно.
