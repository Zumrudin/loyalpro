# База знаний администратора («Папка администратора») — дизайн

Дата: 2026-07-16
Статус: утверждается

## 1. Цель

Новый раздел LoyalPro — внутренний справочник для администраторов салона.
Структурированный, наполняемый контент с быстрым поиском: процедуры и аппараты
(с акцентом на продажи), что выполняют мастера, рабочие скрипты, регламенты,
чек-листы смены, полномочия, правила отмен и работы с жалобами.

**Не AI.** Это структурированная база знаний с полнотекстовым поиском (Postgres,
русская морфология). Ответ пользователю — найденные статьи, а не сгенерированный
текст. Дёшево, просто, полностью в духе текущего стека (Node/Express + PostgreSQL
+ vanilla JS SPA).

## 2. Ключевые решения (согласовано)

- **Модель контента:** единый тип «статья» (markdown) + папки-категории. Никаких
  разных форм под каждый тип — админ просто пишет.
- **Категории — редактируемая таблица** (не хардкод): их много, они нумерованные,
  их будут докручивать. Управление списком папок через интерфейс, порядок drag-drop.
- **Доступ:** читают все роли (owner/admin/specialist), редактируют только
  owner + admin.
- **Журнальные пункты пропущены:** «лист ожидания» и «журнал жалоб и ошибок» — это
  рабочие журналы, а не справка. В v1 не делаем (ни как модуль, ни как статьи).
- **Название пункта меню:** «База знаний» (можно переименовать; концепция —
  «папка администратора»: папки → документы).

## 3. Стартовая структура папок

Наполняется контентом отдельно; здесь — стартовый набор категорий и что кладут внутрь.

| # | Папка | Примеры статей внутри |
|---|-------|-----------------------|
| 1 | 📋 Информация о салоне и услугах | услуги/цены/длительность, что входит, противопоказания, отличия похожих процедур, что можно совмещать, комплексы и программы |
| 2 | 💬 Скрипты для клиентов | первый ответ на заявку, запись нового клиента, презентация цены и ценности, свободные окна, возражение «дорого», доп.услуга, перезапись, возвращение клиента, просьба об отзыве |
| 4 | 📅 Отмены, переносы, опоздания | сроки отмены, удержание предоплаты, поздняя отмена, повторные переносы, ожидание опоздавшего, можно ли сократить процедуру, кто принимает решение |
| 5 | ⚠️ Жалобы и конфликты | алгоритм из 7 шагов + скрипты по ситуациям (недоволен результатом, мастер задерживается, услуга дольше, требует возврат, спор по цене) |
| 6 | 🛡 Полномочия администратора | что можно самому / что только после согласования с руководителем |
| 7 | ✅ Чек-листы смены | Открытие / В течение дня / Закрытие (интерактивные галочки) |
| — | 📁 Документы и регламенты | должностная инструкция, стандарты внешнего вида, график работы, контакты сотрудников, касса и CRM, шаблоны сообщений |
| — | 🎁 Лояльность и акции | программа лояльности, актуальные акции |

Раздел 3 у клиента не показан — добавляется через UI. Список папок полностью
редактируемый, стартовый набор создаётся сидом при первом заходе (см. §7).

## 4. Данные

Две таблицы, обе scoped по `salon_id` (как всё в проекте). Добавляются в
`migrations.js` через `CREATE TABLE IF NOT EXISTS` (безопасно, недеструктивно).

### `kb_categories`
```
id           serial pk
salon_id     int  fk -> salons  (NOT NULL)
title        text NOT NULL
icon         text DEFAULT ''        -- эмодзи/иконка папки
display_order int DEFAULT 0
created_at   timestamptz DEFAULT now()
updated_at   timestamptz DEFAULT now()
```
Индекс: `(salon_id, display_order)`.

### `kb_articles`
```
id            serial pk
salon_id      int  fk -> salons  (NOT NULL)
category_id   int  fk -> kb_categories ON DELETE CASCADE  (NOT NULL)
title         text NOT NULL
body          text DEFAULT ''        -- markdown
tags          text[] DEFAULT '{}'
is_published  boolean DEFAULT true
display_order int DEFAULT 0
search_vector tsvector GENERATED ALWAYS AS (
                setweight(to_tsvector('russian', coalesce(title,'')), 'A') ||
                setweight(to_tsvector('russian', coalesce(body,'')),  'B') ||
                setweight(to_tsvector('russian', array_to_string(tags,' ')), 'A')
              ) STORED
created_at    timestamptz DEFAULT now()
updated_at    timestamptz DEFAULT now()
```
Индексы: GIN на `search_vector`; `(salon_id, category_id, display_order)`.

Заголовок и теги весят выше (`A`) тела (`B`) при ранжировании.

## 5. Backend — `routes/knowledge-base.js`, монтируется на `/api/kb`

Монтируется в specific-prefix блоке `routes/index.js` (рядом с `/api/portfolio`).
Специалистам открывается доступ добавлением `/api/kb` в
`config.SPECIALIST_ALLOWED_PREFIXES`. Все запросы резолвят салон из `req.user.salon_id`.

**Чтение (все роли):**
- `GET /categories` — папки с `articles_count` (только опубликованные), сортировка
  по `display_order`.
- `GET /articles?q=&category_id=&tag=` — поиск/список опубликованных статей.
  - Если `q` задан: ранжирование `ts_rank(search_vector, plainto_tsquery('russian', q))`,
    сниппет через `ts_headline('russian', body, query, 'MaxWords=30, MinWords=15')`
    с подсветкой. Плюс ILIKE-fallback по `title`/`body` для коротких/частичных
    запросов, которых не находит tsquery.
  - Фильтры `category_id` и `tag` комбинируются с поиском.
- `GET /articles/:id` — одна статья целиком (для чтения).

**Редактирование (`requireRole('owner','admin')` — тот же helper, что в `portfolio.js`):**
- `POST /categories`, `PUT /categories/:id`, `DELETE /categories/:id`
  (каскад удаляет статьи; запрет удаления, если это единственная папка — опционально).
- `PUT /categories/reorder` — батч `display_order` (объявлен ДО `/:id`, как в portfolio).
- `POST /articles`, `PUT /articles/:id`, `DELETE /articles/:id`.
- `PUT /articles/reorder` — батч в пределах папки (объявлен ДО `/:id`).

Валидация: `title` обязателен; `category_id` принадлежит тому же салону.

## 6. Frontend — `frontend/js/pages/knowledge-base.js`

Новая страница SPA. Регистрация:
- пункт меню в `index.html` (`#mainNav` и мобильный `#mnavList`) с
  `data-p="knowledge-base"` и `data-roles="owner,admin,specialist"`;
- контейнер `<div class="page" id="page-knowledge-base">`;
- `<script src="js/pages/knowledge-base.js">` перед `app.js`.

**Раскладка (метафора папки):**
- Сверху — крупная строка поиска (живой поиск с debounce ~250мс).
- Слева — список папок с иконками и счётчиками; выбор фильтрует список.
- Центр — карточки-результаты: заголовок, подсвеченный сниппет, папка/теги.
  Клик → чтение статьи (рендер markdown).
- Для owner/admin — кнопки «Добавить статью», «Добавить папку», «Редактировать»,
  drag-drop переупорядочивание папок и статей (как в `portfolio.js`).
  Специалисты видят только чтение и поиск (кнопки редактирования скрыты).

**Markdown-рендерер (встроенный, без внешних зависимостей — в духе vanilla-проекта):**
поддерживает заголовки, **жирный**, списки, переносы, и три полезные вещи:
- `- [ ] пункт` → интерактивная галочка (для чек-листов; состояние в
  `localStorage` per-статья, в БД не хранится, сбрасывается очисткой хранилища);
- код-блоки и статья целиком — с кнопкой «Копировать» (скрипты в один клик в
  переписку с клиентом);
- экранирование HTML на входе (защита от инъекций в пользовательском контенте).

Переиспользуем существующие классы модалок/форм (`stg-section`, `btn-pri`, `fg`/`fl`),
как это сделано в `portfolio.js`.

## 7. Сид стартовых категорий

При первом `GET /categories`, если у салона нет ни одной папки, создаётся стартовый
набор из §3 (idempotent — только когда категорий 0). Так админ сразу видит
структуру и понимает, куда что класть, а не пустой экран.

## 8. Роли и безопасность

- Чтение — все роли; редактирование — owner + admin (проверка на бэкенде через
  `requireRole`, не только скрытием кнопок).
- `/api/kb` добавляется в `SPECIALIST_ALLOWED_PREFIXES`, иначе specialist получит 403.
- Всё scoped по `salon_id`; ни один запрос не выполняется без скоупа.
- Markdown экранируется при рендере (пользовательский контент).

## 9. Границы v1 (YAGNI)

Не входит в v1:
- AI/RAG, семантический поиск, эмбеддинги.
- Рабочие журналы (лист ожидания, журнал жалоб) — отдельная задача при желании.
- Авто-подтяжка контактов сотрудников из таблицы staff — статьёй вручную; авто
  добавим позже, если понадобится.
- Вложения/картинки в статьях, версионирование, черновики сверх флага
  `is_published`.

## 10. Тестирование

- Юнит-тест чистых хелперов бэкенда (построение tsquery, ILIKE-fallback,
  same-salon guard в reorder) — по образцу `portfolio.test.js`, без БД/HTTP.
- Ручная проверка в dev (PM2 `loyalpro`, DB `loyalpro_test`) через Playwright MCP:
  создание папки/статьи, поиск с подсветкой, чек-лист-галочки, копирование,
  доступ specialist (только чтение), скоуп по салону.
