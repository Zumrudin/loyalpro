<objective>
Wave 4 — финальный шаг: подключить `syncGoodsCatalog` в существующий cron `0 */3 * * *` Europe/Moscow handler в `backend/server.js`, и выполнить **ручной production cutover** — единоразовый запуск sync-а для всех активных салонов с YClients-кредами, чтобы заполнить `yclients_goods_catalog` сразу, не дожидаясь следующего cron-такта.

После этой Wave:
- Cron автоматически обновляет каталог каждые 3 часа.
- На тестовом стенде salon_id=1 (PERI CLINIC) каталог содержит ≥ 240 не-архивных товаров.
- Дропдаун в шаблоне «Домашний уход» показывает все актуальные SKU из YClients.
- Phase goal достигнут.

Purpose:
1. **Cron wiring** — без него каталог никогда не обновится; Wave 2 + Wave 3 без этой строки бесполезны.
2. **Ручной cutover** — без него врачи увидят пустой дропдаун до следующего natural cron-tick (до 3 часов). Cutover превращает Wave 3 endpoints из "архитектурно готовых" в "живые".
3. **Smoke verification** — финальный gate перед `/gsd-verify-work`. Доказывает, что вся цепочка bootstrap → enumerate → upsert → archive → cache invalidation → endpoint serving работает на реальных данных PERI CLINIC.

Это план с одним checkpoint'ом (`checkpoint:human-verify`) — потому что smoke включает в себя ручную проверку дропдауна в браузере (frontend), что нельзя автоматизировать без полноценного e2e-теста (out-of-scope для этой фазы).

Output:
- 2 строки изменений в `backend/server.js` (require + 1 строка в cron handler).
- Одноразовый node-скрипт ran через `node -e` на тестовом стенде.
- Заполненная таблица `yclients_goods_catalog` для активных салонов.
- Visual подтверждение работы дропдауна.
