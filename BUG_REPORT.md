# 🐛 ОТЧЁТ О ПРОБЛЕМЕ И ИСПРАВЛЕНИИ

## ПРОБЛЕМА
При попытке авторизации на фронте возникала ошибка:
```
Unexpected token '<', "<!DOCTYPE "... is not valid JSON
```

## ПРИЧИНА ОШИБКИ
В файле `/root/loyalpro/frontend/js/core/api.js` функция `api()` пыталась распарсить ответ как JSON **ДО** проверки статуса HTTP-ответа.

### Проблемный код (строки 13-14):
```javascript
const r = await fetch(API + path, o);
const j = await r.json();                    // ❌ Попытка парсить JSON до проверки статуса
if (!r.ok) throw new Error(j.error || 'HTTP ' + r.status);
```

**Что происходит:**
1. Когда сервер возвращает ошибку (404, 500 и т.д.), он может вернуть HTML вместо JSON
2. Код пытается распарсить HTML как JSON (`r.json()`)
3. JSON парсер выбрасывает ошибку: `Unexpected token '<'` (начало `<!DOCTYPE`)
4. Проверка статуса никогда не выполняется, т.к. исключение выброшено раньше

## ИСПРАВЛЕНИЕ
Переместили проверку статуса HTTP **ДО** попытки парсинга JSON:

### Исправленный код:
```javascript
const r = await fetch(API + path, o);

// ✅ Проверяем статус ПЕРЕД парсингом JSON
if (!r.ok) {
  try {
    const j = await r.json();
    throw new Error(j.error || 'HTTP ' + r.status);
  } catch (e) {
    // Если сервер вернул HTML вместо JSON (ошибка 404, 502 и т.д.)
    if (e instanceof SyntaxError) {
      throw new Error('Ошибка сервера (HTTP ' + r.status + ')');
    }
    throw e;
  }
}

const j = await r.json();
return j;
```

## ПРЕИМУЩЕСТВА ИСПРАВЛЕНИЯ
✅ Правильная обработка ошибок сервера (404, 500 и т.д.)
✅ Поддержка как JSON, так и HTML ответов при ошибках
✅ Более понятные сообщения об ошибках пользователю
✅ Предотвращение ошибок парсинга при некорректных ответах
