# Исследование API YClients для получения сообщений клиентов

## 📋 Задача

Нужно реализовать модуль работы с переписками клиентов в LoyalPro:
- Получать сообщения из YClients (Telegram, WhatsApp, MAX и т.д.)
- Интегрировать в вкладку "Чат" на главном экране
- Иметь возможность обрабатывать и анализировать сообщения для дальнейших функций

## 🔍 Известные факты о текущей системе

### Что уже есть
- `clients.telegram_id` — Telegram ID клиента сохраняется в БД
- `records` — есть таблица записей со всеми данными о визитах
- YClients API интеграция уже работает (синхронизация клиентов, записей, карт лояльности)
- HTTP куки для веб-авторизации в YClients (для скрейпинга, где API недостаточно)

### Текущее состояние сообщений
На главном экране есть вкладка "Чат" с сообщениями из разных мессенджеров (Telegram, MAX, WhatsApp), но неясно:
- Где эти сообщения хранятся
- Как они попадают в систему
- Есть ли API для их получения

## 📚 Подходы к получению сообщений

### ✅ Вариант 1: YClients REST API
**Проверить наличие:**
- `/company/{company_id}/messages` или `/messages`
- `/client/{company_id}/{client_id}/messages`
- `/company/{company_id}/chats`
- `/messengers` — информация о подключенных мессенджерах

**Преимущества:**
- Официальный, поддерживаемый способ
- Безопасен и надежен
- Работает со всеми мессенджерами одновременно

**Недостатки:**
- Если API нет, нужен альтернативный способ

---

### ✅ Вариант 2: YClients Webhook интеграция
**Описание:**
YClients может отправлять события (включая новые сообщения) через webhook на ваш сервер.

**Преимущества:**
- Real-time получение сообщений
- Не нужно постоянно опрашивать API
- Экономит лимиты API

**Недостатки:**
- Нужна настройка на стороне YClients
- Требует публичного URL сервера

**Реализация:**
```javascript
// В server.js добавить endpoint:
app.post('/webhooks/yclients/message', (req, res) => {
  // Обработать входящее сообщение от YClients
  const { client_id, message, messenger_type, timestamp } = req.body;
  // Сохранить в БД
  // Отправить в UI через WebSocket (если нужен real-time)
  res.json({ ok: true });
});
```

---

### ✅ Вариант 3: Прямая интеграция с мессенджерами
**Описание:**
Получать сообщения напрямую из API мессенджеров (Telegram Bot API, WhatsApp Business API и т.д.)

**Преимущества:**
- Полный контроль над данными
- Можно получить больше информации
- Не зависит от YClients

**Недостатки:**
- Нужна отдельная интеграция для каждого мессенджера
- Усложняет архитектуру
- Нужны API токены для каждого мессенджера

**Примеры:**
- Telegram: Bot API / Long Polling / Webhooks
- WhatsApp: WhatsApp Business API (платный)
- MAX: собственный API (проверить документацию)

---

### ✅ Вариант 4: Скрейпинг веб-интерфейса YClients
**Описание:**
Парсить сообщения из веб-интерфейса YClients (как уже делается для транзакций карт).

**Преимущества:**
- Работает, если API недоступен
- Можно получить исторические сообщения

**Недостатки:**
- Хрупкий (может сломаться при изменении HTML)
- Медленнее API
- Может быть заблокирован YClients

### Этап 3: Дизайн БД
Создать таблицу для сообщений:
```sql
CREATE TABLE messages (
  id SERIAL PRIMARY KEY,
  salon_id INTEGER NOT NULL,
  client_id INTEGER NOT NULL,
  messenger_type VARCHAR(50), -- 'telegram', 'whatsapp', 'max'
  message_text TEXT,
  sender_type VARCHAR(20), -- 'client' или 'salon_staff'
  external_id VARCHAR(255), -- ID сообщения в YClients/мессенджере
  created_at TIMESTAMP,
  synced_at TIMESTAMP,
  FOREIGN KEY (client_id) REFERENCES clients(id),
  FOREIGN KEY (salon_id) REFERENCES salons(id)
);

CREATE INDEX idx_messages_client ON messages(salon_id, client_id, created_at DESC);
```
