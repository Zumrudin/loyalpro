🚀 ЧТО ДЕЛАТЬ СЕЙЧАС
═══════════════════════════════════════════════════════════════════════════════

1️⃣ ПОДГОТОВКА

   Нужны данные для YClients API:
   • Partner Token — из настроек YClients
   • User Token — получить через API авторизацию
   • Company ID — ID вашей компании в YClients

   Способ 1 (рекомендуется) — создать .env файл:
   ─────────────────────────────────────────────────
   YCLIENTS_PARTNER_TOKEN=your_partner_token
   YCLIENTS_USER_TOKEN=your_user_token
   YCLIENTS_COMPANY_ID=your_company_id

   Способ 2 — отредактировать скрипт:
   ─────────────────────────────────────────────────
   nano yclients-messages-explore.js
   # Строки 18-21, замените YOUR_*_HERE на реальные значения


2️⃣ ЗАПУСТИТЬ ИССЛЕДОВАНИЕ

   cd /root/loyalpro/backend
   node yclients-messages-explore.js

   Или сохранить результаты в файл:
   node yclients-messages-explore.js > results.txt 2>&1


3️⃣ ПРОАНАЛИЗИРОВАТЬ РЕЗУЛЬТАТЫ

   Ищите в выводе:
   ✅ Какие endpoints вернули Success?
   ✅ Какая структура данных?
   ✅ Есть ли поля messenger_type, created_at, text?

   Примеры результатов см. в RUN_MESSAGE_TEST.md


4️⃣ ВЫБРАТЬ ПОДХОД

   Результат А (API работает) → Фаза 2A (REST API)
   Результат B (API нет) → Фаза 2B (Webhook)
   Результат C (другое) → Фаза 2C (Прямая интеграция)

   Подробнее в MESSAGES_MODULE_PLAN.md


5️⃣ ЗАПУСТИТЬ РАЗРАБОТКУ

   После выбора подхода:
   1. Создать миграцию БД (MESSAGES_DB_SCHEMA.sql)
   2. Реализовать синхронизацию
   3. Обновить UI
   4. Тестировать

❓ ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
═══════════════════════════════════════════════════════════════════════════════

Ошибка 401 (Unauthorized):
→ Проверить корректность Partner Token и User Token

Ошибка 404 (Endpoint not found):
→ Это нормально, API может не иметь endpoint для сообщений
→ Смотреть Фаза 2B (Webhook) или 2C (Прямая интеграция)

Таймаут:
→ Может быть проблема с сетью
→ Подождать и повторить

Другие ошибки:
→ Смотреть логи скрипта (весь вывод)
→ Проверить документацию YClients
→ Открыть issue в проекте
